## 这一版在做什么

个体学习不是「网络有一个全局模型」，而是**每个 Agent 用自己的经验改变自己接下来的行为参数**：

```text
经验收集 → 反馈分析 → 行为调整 → 效果评估 → 经验更新
   ↑                                              │
   └──────────────────────────────────────────────┘
```

学习信号 = 任务完成质量 / 结算金额 / 信誉变化 / 违规记录。
被调整的策略 = **定价策略 / 任务选择策略 / 协作对象选择策略**。
隐私 = 本地经验库 + 对外公开视图脱敏。
效果 = 学习组 vs 对照组（固定种子、可复现），输出成功率与收益提升。

## v1.6.1 经验库（status: done）

### 目标

让 Agent 能把自己的经历写成**可寻址、有界、可重放**的数据结构：同一条语义经验只有一个字节表示，
重复记录被精确识别，容量满时淘汰可见，经验库可导出/载入而不接受被篡改的内容。

### 交付物

* `src/experience.rs`：`Outcome`（Success/Failure/Partial，质量 10000/5000/0 基点）、
  `Experience { task_id, task_type, context, action, outcome, reward, timestamp, peer_agents }`、
  `ExperienceStore`（容量、内容键索引、FIFO 淘汰计数、规范 JSON 摘要、载入校验）。
* `src/rng.rs`：`SplitMix64`（拒绝采样去偏置）+ 无状态 `hash64`/`hash_bp`，
  后续版本的抽样与市场生成都建立在它之上（**不引入随机库**，保证可重放）。
* `src/scenario.rs`：端到端入口（自主注册 → 收集 24 条经验 → 返回摘要）。
* `tests/experience_store.rs`：10 个集成测试。

### 接口

```rust
pub enum Outcome { Success, Failure, Partial }          // quality_bp(): 10000 / 5000 / 0
pub struct Experience {
    pub task_id: String, pub task_type: String, pub context: String, pub action: String,
    pub outcome: Outcome, pub reward: Credits, pub timestamp: u64, pub peer_agents: Vec<Did>,
}
impl Experience {
    pub fn new(..., peers: &[Did]) -> CoreResult<Self>;   // 先规范化（升序去重）再校验
    pub fn normalize(&mut self);
    pub fn validate(&self) -> CoreResult<()>;
    pub fn key(&self) -> CoreResult<String>;              // 规范 JSON 的 SHA-256
}
pub struct ExperienceStore { /* 有界、追加序即证据序 */ }
impl ExperienceStore {
    pub fn new(capacity: usize) -> CoreResult<Self>;
    pub fn record(&mut self, exp: Experience) -> CoreResult<RecordOutcome>;
    pub fn canonical_json(&self) -> CoreResult<String>;
    pub fn from_json_str(s: &str) -> CoreResult<Self>;    // 重建索引 + 校验不变式
    pub fn digest(&self) -> CoreResult<String>;
    pub fn stats(&self) -> StoreStats;
}
pub enum RecordOutcome { Added { key }, Duplicate { key }, Evicted { key, evicted } }
```

### 验收（断言了什么）

1. 同一条经验记录两次 → `RecordOutcome::Duplicate`，库里仍只有 1 条（`duplicates == 1`）。
2. 容量 3 的库写 4 条 → 淘汰最旧一条且 `evictions == 1`、`len == 3`，淘汰事实被返回。
3. 空 `task_id` / 含空格的任务类型 / 空或超长（>512 字节）上下文 / 控制字符 / 17 个协作者 /
   未升序协作者 / 容量 0 → 全部 `Err(CoreError::InvalidKind)`。
4. 协作者输入 `[p2, p0]` 与 `[p0, p2]` → 归一化后同一个内容键。
5. 相同构建序列跑两次 → `canonical_json()` 与 64 位 hex 摘要逐字节相同。
6. 规范 JSON 往返后摘要不变；序列化里塞重复条目 / 非法字段 / `capacity < len` → 拒绝，非 JSON → `Encoding`。
7. `scenario` 在默认内核上跑两次结果相同（`assert_eq!(a, b)`）；同一内核上重复调用不触发
   `DuplicateAgent`（幂等 `ensure_agent`）；质押 10 微积分进入 `locked`；账本守恒。
8. `self_check()` 全绿且 ≥5 项，`results_json()` 的 `all_passed == true`，且能被规范 JSON 编码（无浮点）。

## v1.6.2 反馈机制（status: done）

### 目标

把原始经验聚合成**可比较的统计**（整体 / 按任务类型 / 按协作者），并显式回答「这批数据够不够支撑一次行为改变」；
成功经验通过**共享内核账本**真实结算，让「结算金额」成为可核对的信号而不是自报数字。

### 交付物

* `src/feedback.rs`：`Feedback`、`PeerFeedback`、`FeedbackReport`、`FeedbackAnalyser`、`confidence_of`、`MIN_SAMPLES`。
* `src/scenario.rs`（扩展）：反馈阶段 + 结算阶段（`EvidenceGrade::CpuProto`，金额不预钳制，闸门拒绝被计数）。
* `tests/feedback.rs`：10 个集成测试。

2. 7 条（2/2/3）→ `2857 + 2857 + 4286 == 10000`（互补取整，三率和恒为 10000）。
3. 1 条样本 → `sufficient=false` 且 `confidence_bp=2500`；空库 → 全零报告而不是错误。
4. 协作者统计精确：peer0 两次成功 → `success_bp=10000, mean_reward=25`；peer1 两次失败 → `success_bp=0, quality_bp=0`；
   peer2 一次部分 → `quality_bp=5000`；多参与者任务里 3 个协作者都被计入。
5. 公开投影 `public_json()` 的 JSON 文本**不含** `did:au4a:`、**不含** `SECRET-CONTEXT`，也没有 `per_peer` 字段；

6. 报告可复现：两次分析摘要相同；改变一条经验的结局 → 摘要改变；报告可被规范 JSON 编码（无浮点）。
7. 端到端：`settled_total == successes × 40`、`settlement_refused == 0`、`agents == 4`、`feedback.total == 24`、

8. 拒绝路径：把 `cpu_proto_settle_cap` 压到 0 → 证据闸门拒付，`settled_total == 0`、

## v1.6.3 行为调整（status: done）

### 目标

让学习**真的改变行为**：把反馈统计与学习信号变成三个策略参数（定价 / 任务选择 / 协作对象选择）的下一个取值，
并用一个对照实验量化「改变之后是不是真的更好」——而不是打印一句「已学习」。

### 交付物

* `src/policy.rs`：`PolicyParams`、`PolicyBounds`、`PolicyTargets`、`Signals`、`PolicyAdjustment`、`adjust()`、`task_score_bp()`。
* `src/violation.rs`：`Violation`、`ViolationLog`（违规单独记账、按协作者计数、公开投影脱敏）。
* `src/sim.rs`：合成任务市场 + `ab_test()`（学习组 vs 对照组，同种子同一市场）+ `Comparison`。
* `src/scenario.rs`（扩展）：用 24 条经验做一次真实行为调整 + 跑一遍对照实验。
* `tests/policy.rs`（9 个）、`tests/market.rs`（10 个）。

### 接口

```rust
pub struct PolicyParams { pub price_bp: i64,
                          pub task_bias_bp: BTreeMap<String, i64>,
                          pub peer_bias_bp: BTreeMap<Did, i64> }   // PolicyParams::baseline() = 12000bp + 均匀偏好
pub struct PolicyBounds { price_min_bp, price_max_bp, bias_min_bp, bias_max_bp, price_step_bp, bias_step_bp }
pub struct PolicyTargets { accept_rate_target_bp, accept_deadband_bp, min_confidence_bp,
                           violation_penalty_bp, reward_ref, reward_noise_floor_bp }
pub struct Signals { sample, confidence_bp, accept_rate_bp: Option<i64>, success_bp,
                     mean_reward, prev_mean_reward, prev_price_dir, violations, reputation_delta }
pub fn adjust(&PolicyParams, &FeedbackReport, &ViolationLog, &Signals,
              &PolicyBounds, &PolicyTargets) -> CoreResult<PolicyAdjustment>;
pub fn task_score_bp(&Feedback, Credits) -> i64;                       // 质量 2/3 + 收益 1/3
pub fn ab_test(&MarketConfig) -> CoreResult<(MarketRun, MarketRun, Comparison)>;
pub fn compare(&MarketRun, &MarketRun) -> CoreResult<Comparison>;      // 不同市场直接报错
```

三条更新规则（全整数、全基点）：

| 策略 | 规则 |
|---|---|
| 定价 | 接受率偏离目标区间（8500±500bp）就朝目标走一步；**收益指数移动平均**跌破 3% 死区时反向（安全阀） |
| 任务选择 | `(质量×2 + 归一化收益)/3` 与整体评分之差 /20，按 ±250bp 封顶 |
| 协作对象 | 协作者质量与整体质量之差 /20 封顶，**叠加违规惩罚 −2000bp** |

### 验收（断言了什么）

1. `confidence_bp < min_confidence_bp` → 参数与理由都记 `evidence-below-threshold`，`changed == false`、三个杠杆都没动。
2. 证据充分时三个杠杆同时动且方向正确：接受率 3000bp → 降价 500bp；`good.type` 偏好上升、`bad.type` 下降；
   `peer0` 上升、`peer1` 下降；每条理由都能追溯到输入数据（`reasons` ≥ 4 条且前缀分类正确）。
3. 接受率在死区内 → 价格不动（收敛点）；接受率 9800bp → +500bp。
4. 平滑收益跌破死区 → 反向；收益改善 → 沿原方向继续。
5. 违规协作者偏好单调更低（同一输入下 `-2000bp` 惩罚生效），理由里出现 `violations=1`。
6. 边界：价格已在上界时 `price_moved_bp == 0`；所有偏好落在 `[bias_min, bias_max]`；非法边界
   → `CoreError::NegativeAmount`，非法 `min_confidence_bp` → `CoreError::InvalidKind`。
7. `task_score_bp` 精确整数：整体 4666bp、`good.type` 9333bp、`reward_ref == 0` 时降级为纯质量分。
8. 公开投影（`PolicyParams::public_json` / `PolicyAdjustment::public_json`）**不含 `did:au4a:`**；理由文本用 DID 的
   摘要前缀标识协作者（`peer_tag`），避免解释文本自己破坏脱敏不变式。
9. 市场对照实验（16 轮 × 12 tick = 192 tick/组，同种子）：
   * 对照组参数**完全冻结**（价格路径恒为 12000bp），学习组参数真的变了（价格 12000 → 9000bp、
     3 个任务类型偏好、8 个协作者偏好）。
   * 第一轮两组的市场结果逐字段相同 → 两组确实面对同一个市场；分歧从第二轮开始。
   * 违规协作者偏好全部为负，偏好最高的协作者不是恶意协作者。
   * 两次独立 `ab_test` 的跑批摘要与对比报告逐字节一致；换种子 → 不同的对比报告。
   * `compare()` 对「不同种子/不同 tick 数」的两组直接返回 `CoreError::InvalidKind`，不给出似是而非的结论。
10. 非法配置（`rounds=0`、`ticks_per_round < MIN_SAMPLES`、`peers<2`、`peers>16`、负噪声）全部被拒。

| 指标 | 对照组（不学习） | 学习组 | 提升 |
|---|---|---|---|
| 成功率 | 2239 bp | 4583 bp | **+2344 bp** |
| 接受率 | 4010 bp | 6979 bp | +2969 bp |

### 一次真实失败（保留在案，不粉饰）

v1.6.3 的第一版实现把定价方向交给「相邻两轮原始收益的比较」（收益变好就继续、变差就反向）。

## v1.6.4 学习信号（status: done）

### 目标

把 spec 规定的四类学习信号（**任务完成质量 / 结算金额 / 信誉变化 / 违规记录**）折算成一个统一的整数向量，
并让它们**真的参与决策**（否则「信号」只是一个被记录后丢掉的结构体）。

### 交付物

* `src/signal.rs`：`SignalWeights`、`LearningSignal`（四类原始值 + 四个归一值 + `composite_bp`）。
* `src/policy.rs`（扩展）：信誉下降时**冻结涨价**——让「信誉变化」这类信号真的改变行为。
* `src/sim.rs`（扩展）：每轮用 `LearningSignal::from_store` 生成信号并喂给 `adjust()`；
  `RoundStats.signal_composite_bp` 把每轮综合信号打进证据。
* `src/scenario.rs`（扩展）：端到端摘要里输出 `learning_signal`。
* `tests/signal.rs`：8 个集成测试。

### 接口

```rust
pub struct SignalWeights { quality_bp: 5000, settled_bp: 2500, reputation_bp: 1500,
                           violation_bp: 1000, reward_ref: Credits(100), reputation_ref: 100 }
pub const VIOLATION_UNIT_BP: i64 = 2500;
pub struct LearningSignal { quality_bp, settled, reputation_delta, violations,
                            quality_norm_bp, settled_norm_bp, reputation_norm_bp,
                            violation_norm_bp, composite_bp }
impl LearningSignal {
    pub fn compute(quality_bp, settled, reputation_delta, violations, &SignalWeights) -> CoreResult<Self>;
    pub fn from_experience(&Experience, &ViolationLog, &SignalWeights) -> CoreResult<Self>;
    pub fn from_store(&ExperienceStore, &ViolationLog, reputation_delta: i64, &SignalWeights) -> CoreResult<Self>;
    pub fn to_signals(&self, sample, accept_rate_bp, mean_reward, prev_mean_reward, prev_price_dir) -> Signals;
}
```

折算规则（全整数，`10000` = 满格）：质量直接取 `Outcome`（10000/5000/0）；结算
`min(settled/reward_ref, 1)×10000`；信誉 `clamp(delta/reputation_ref, ±1)×10000`；违规
`min(count,4)×2500` 作为扣分项。综合 = Σ(归一值×权重)/10000，钳制 ±10000。

### 验收（断言了什么）

1. 质量 5000 + 结算 50/100 + 信誉 +50/100 + 无违规 → 归一值 (5000, 5000, 5000, 0)、综合 **4500bp**（精确加权）。
2. 四类全满 → **9000bp**（余下 1000 是只在扣分时出现的违规权重）；四类全负 → **−2500bp**。
3. 每一类信号方向正确：质量↑、结算↑、信誉↑ → 综合↑；信誉↓、违规↑ → 综合↓；
   结算 500/100 封顶 10000bp；信誉 −1000/100 钳制 −10000bp；违规第 4 条起吃满（第 9 条不再变）。
4. `from_experience` 只统计**该条经验参与者**的违规：同一经验库下，与有违规协作者合作的信号严格低于与干净协作者合作的信号。
5. `from_store`：质量取平均（10000+10000+5000+0)/4 = **6250bp**、结算求和 **100 微积分** → 归一 10000bp；空库 → 零信号而不是错误。
6. 权重校验：负权重 → `NegativeAmount`；权重和 >10000 → `InvalidKind`；`reward_ref = 0` / `reputation_ref = 0` → `InvalidKind`；
   自定义权重真的改变结论（质量权重置 0 后质量差异不再影响综合值）。
7. `to_signals` 映射：`success_bp = 质量信号`、`violations` / `reputation_delta` 透传、置信度由样本数折算。
8. **信号真的改变行为**：接受率 9800bp（想涨价）时，`reputation_delta = 0` → `price_moved_bp = +500`；
   `reputation_delta = −40` → `price_moved_bp = 0` 且理由含「冻结涨价」，而任务偏好照常调整。
