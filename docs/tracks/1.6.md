## 这一版在做什么

个体学习不是「网络有一个全局模型」，而是**每个 Agent 用自己的经验改变自己接下来的行为参数**：

```text
经验收集 → 反馈分析 → 行为调整 → 效果评估 → 经验更新
   ↑                                              │
   └──────────────────────────────────────────────┘
```

学习信号 = 任务完成质量 / 结算金额 / 信誉变化 / 违规记录。
被调整的策略 = **定价策略 / 任务选择策略 / 协作对象选择策略**。
隐私 = 本地经验库 + 对外公开视图脱敏。
效果 = 学习组 vs 对照组（固定种子、可复现），输出成功率与收益提升。

## v1.6.1 经验库（status: done）

### 目标

让 Agent 能把自己的经历写成**可寻址、有界、可重放**的数据结构：同一条语义经验只有一个字节表示，
重复记录被精确识别，容量满时淘汰可见，经验库可导出/载入而不接受被篡改的内容。

### 交付物

* `src/experience.rs`：`Outcome`（Success/Failure/Partial，质量 10000/5000/0 基点）、
  `Experience { task_id, task_type, context, action, outcome, reward, timestamp, peer_agents }`、
  `ExperienceStore`（容量、内容键索引、FIFO 淘汰计数、规范 JSON 摘要、载入校验）。
* `src/rng.rs`：`SplitMix64`（拒绝采样去偏置）+ 无状态 `hash64`/`hash_bp`，
  后续版本的抽样与市场生成都建立在它之上（**不引入随机库**，保证可重放）。
* `src/scenario.rs`：端到端入口（自主注册 → 收集 24 条经验 → 返回摘要）。
* `tests/experience_store.rs`：10 个集成测试。

### 接口

```rust
pub enum Outcome { Success, Failure, Partial }          // quality_bp(): 10000 / 5000 / 0
pub struct Experience {
    pub task_id: String, pub task_type: String, pub context: String, pub action: String,
    pub outcome: Outcome, pub reward: Credits, pub timestamp: u64, pub peer_agents: Vec<Did>,
}
impl Experience {
    pub fn new(..., peers: &[Did]) -> CoreResult<Self>;   // 先规范化（升序去重）再校验
    pub fn normalize(&mut self);
    pub fn validate(&self) -> CoreResult<()>;
    pub fn key(&self) -> CoreResult<String>;              // 规范 JSON 的 SHA-256
}
pub struct ExperienceStore { /* 有界、追加序即证据序 */ }
impl ExperienceStore {
    pub fn new(capacity: usize) -> CoreResult<Self>;
    pub fn record(&mut self, exp: Experience) -> CoreResult<RecordOutcome>;
    pub fn canonical_json(&self) -> CoreResult<String>;
    pub fn from_json_str(s: &str) -> CoreResult<Self>;    // 重建索引 + 校验不变式
    pub fn digest(&self) -> CoreResult<String>;
    pub fn stats(&self) -> StoreStats;
}
pub enum RecordOutcome { Added { key }, Duplicate { key }, Evicted { key, evicted } }
```

### 验收（断言了什么）

1. 同一条经验记录两次 → `RecordOutcome::Duplicate`，库里仍只有 1 条（`duplicates == 1`）。
2. 容量 3 的库写 4 条 → 淘汰最旧一条且 `evictions == 1`、`len == 3`，淘汰事实被返回。
3. 空 `task_id` / 含空格的任务类型 / 空或超长（>512 字节）上下文 / 控制字符 / 17 个协作者 /
   未升序协作者 / 容量 0 → 全部 `Err(CoreError::InvalidKind)`。
4. 协作者输入 `[p2, p0]` 与 `[p0, p2]` → 归一化后同一个内容键。
5. 相同构建序列跑两次 → `canonical_json()` 与 64 位 hex 摘要逐字节相同。
6. 规范 JSON 往返后摘要不变；序列化里塞重复条目 / 非法字段 / `capacity < len` → 拒绝，非 JSON → `Encoding`。
7. `scenario` 在默认内核上跑两次结果相同（`assert_eq!(a, b)`）；同一内核上重复调用不触发
   `DuplicateAgent`（幂等 `ensure_agent`）；质押 10 微积分进入 `locked`；账本守恒。
8. `self_check()` 全绿且 ≥5 项，`results_json()` 的 `all_passed == true`，且能被规范 JSON 编码（无浮点）。
