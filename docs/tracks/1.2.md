# 轨道 1.2 — Negotiation 协商协议（v1.2.1 → v1.2.10）

* crate：`crates/au4a-negotiate`
* 中版本代号：Negotiation 协商协议
* 依赖：`au4a-core`（冻结基元）、`au4a-kernel`（宿主内核）、`serde`、`serde_json`
* 测试：`$env:CARGO_TARGET_DIR = "E:\DS\_forangent\target\au4a-negotiate"; cargo test -p au4a-negotiate`
* 原则：协商是**Agent 之间**的协议。人类只能通过 `Kernel::observe()` 只读观察；
  本 crate 不提供任何「人类发起 / 人类批准 / 人类裁决」的路径。

## 规格映射（brief 必做语义 → 代码）

| 规格要求 | 落地位置 |
|---|---|
| PMB 消息类型 `NEGOTIATE_REQUEST/COUNTER/ACCEPT/REJECT`、`CONTRACT_SIGN/BREACH` | `src/msg.rs`：`kinds::*` 六个常量 + `NegotiationMsg` 六变体 |
| 状态机 `IDLE→NEGOTIATING→ACCEPTED→CONTRACT_SIGNED→EXECUTING→SETTLED`，违约进 `ARBITRATION` | `src/state.rs`（v1.2.2） |
| 每次状态转换双方签名 | `src/state.rs`：`TransitionRecord` 双签 + 合约条款授权（v1.2.2 起） |
| 合约哈希 = 规范 JSON 的 SHA-256，可锚定 | `src/contract.rs`（v1.2.5） |
| 协商记录可导出/重放且逐字节一致 | `src/journal.rs`（v1.2.3） |
| 报价轮数上限（REJECT 不占额度） | `src/rounds.rs`（v1.2.4） |

## v1.2.1 消息类型

* **目标**：把六种协商消息做成「先签名后发送」的 PMB 信封，并给出可往返解析的语义体。
* **交付物**
  * `src/msg.rs`：`kinds`（六个 PMB 类型名）、`ALL_KINDS`、`Terms`（整数微积分条款 + 规范哈希）、
    `BreachKind`、`NegotiationMsg`（六变体、内部 `type` 标签）、`session_id` 内容寻址、`is_hash`/`is_label`。
  * `src/lib.rs`：`self_check()` 四条真实断言、`results_json()`、`scenario()`（两 Agent 真实投递 request+counter）。
  * `tests/messages.rs`：六种消息经内核投递的集成测试。
* **接口**：`NegotiationMsg::{request,counter,accept,reject,sign_contract,breach}`、`::signed(&AgentKeys,&Did,ts,in_reply_to)`、
  `::from_env(&Envelope)`、`Terms::new/hash`、`msg::session_id`。
* **验收**（断言，非「应该」）
  1. 六个类型名都通过 `MsgKind::new` 且互不相同（`ALL_KINDS.len()==6`）。
  2. 六种消息各自「构造 → 签名 → 信封验签 → 解析」后与原消息逐字段相等。
  3. 信封 kind 与消息体 `type` 不一致 → `CoreError::InvalidKind`。
  4. 篡改 body → `CoreError::InvalidSignature`；未封口 → `CoreError::NotSealed`；伪造信封在内核里记为 `unauthorized`（恶意码）。
  5. 条款哈希对同一语义稳定、对价格敏感；`price<=0`、非法标签、非 hex 哈希、超长文本全部被拒。
  6. `session_id` 绑定（提议方, 应答方, 首轮条款），换任一项都不同。
* **证据**（v1.2.1 实测，本机 Windows）
  * 命令：`$env:CARGO_TARGET_DIR = "E:\DS\_forangent\target\au4a-negotiate"; cargo test -p au4a-negotiate`
  * 结果：**exit=0，14 passed / 0 failed / 0 warning**（8 个 `src/msg.rs` 单元测试 + 6 个 `tests/messages.rs` 集成测试）；
    日志 `E:\DS\_forangent\logs\1.2-v1.2.1.log`。
  * 等级：`cpu-proto`。真实执行：Ed25519 签名/验签、规范 JSON（AU4A-CJ）哈希、PMB 分帧、内核投递、
    恶意拒绝分类（伪造信封 → `unauthorized` → `Quarantine`）。原型：传输是同进程内存队列，不是真实 libp2p 网络。
* **状态**：done

## v1.2.2 状态机

* **目标**：`IDLE→NEGOTIATING→ACCEPTED→CONTRACT_SIGNED→EXECUTING→SETTLED` 与违约进 `ARBITRATION`；
  非法转换必须被拒；每次转换双方签名。
* **交付物**
  * `src/state.rs`：`Phase`（7 相位）、`Event`（9 事件）、`LEGAL_TRANSITIONS`（10 条合法转换表）、
    `transition()`（纯函数，非法即 `Err`）、`Basis`（双签 / 合约条款）、`PartySignature`、
    `TransitionRecord`（携带签名，`verify`/`verify_against`/`record_hash`）、`StateMachine`（`stage`/`co_sign`/`commit`/`transact`/`verify_history`）、
    `DualSigned`（双签合约的窄见证接口，为 v1.2.5 预留）。
  * `tests/state_machine.rs`：完整生命周期、违约进仲裁、非法事件不改状态、第三方推动被拒。
* **接口**：`transition(Phase, Event) -> CoreResult<Phase>`、`StateMachine::{open,stage,stage_under_contract,co_sign,commit,transact,verify_history}`
* **验收**（断言，非「应该」）
  1. **穷举**：7 相位 × 9 事件 = 63 种组合逐一比对合法表 —— 恰好 10 合法、53 非法且全部 `Err(InvalidKind)`。
  2. `SETTLED` 是终态：9 个事件全部被拒。
  3. 完整路径 `IDLE→…→SETTLED` 的 8 次转换每条记录都恰好 2 个签名（双方各一）。
  4. 单签 `commit` → `NotSealed` 且相位/历史不变；第三方联署 → `InvalidSignature`；同方重复签名 → `InvalidSignature`。
  5. 签名后篡改 `event`/`to`/`at` 任一字节 → 验签失败（签名覆盖全字段）。
  6. `REJECT` 不占轮数额度（3 次拒绝后 `round==0`），`COUNTER` 每次 +1。
  7. 违约进仲裁只接受 [`Basis::ContractClause`]，且必须出示**双签**合约见证；缺见证 → `NotSealed`，单签合约/哈希不符 → `InvalidSignature`。
  8. `verify_history` 能抓出被篡改的历史项，并对未篡改的历史复算同一末端哈希。
* **证据**（v1.2.2 实测）
  * 命令：`cargo test -p au4a-negotiate`；结果：**exit=0，30 passed / 0 failed / 0 warning**
    （19 个单元 + 6 个 `tests/messages.rs` + 5 个 `tests/state_machine.rs`）；日志 `E:\DS\_forangent\logs\1.2-v1.2.2.log`。
  * 等级：`cpu-proto`（同 v1.2.1：密码学与状态机真实执行，传输仍是同进程内存队列）。
  * 修复记录：首轮运行 5 个测试失败，原因是 `commit` 把同一条记录应用了两次（`round` 多加 1、历史重复）；
    已把「校验」与「推进」拆成 `check_chain` / `apply` 并复跑全绿——这是真实运行抓出来的缺陷，不是事后编的故事。
* **状态**：done

## v1.2.3 持久化

* **目标**：协商记录导出为规范 JSON 快照并可重放；重放后**逐字节一致**。纯内存，**无文件 I/O**。
* **交付物**
  * `src/journal.rs`：`Journal`（唯一事实来源 = 已签名信封 + 双方签署的转换记录；相位/序号/轮数全部由重放推导）、
    `Snapshot`（`deny_unknown_fields`）、`encode`/`decode`/`replay`/`replay_digest`/`stats`。
  * `src/state.rs`：新增 `StateMachine::rebuild`（归档重放路径：逐条重新验签 + 重走相位链）。
  * `tests/journal.rs`：真实投递后再归档、篡改/错版本/乱序/单签拒绝。
* **接口**：`Journal::{open,append,append_transition,encode,decode,replay,replay_digest}`、`JOURNAL_VERSION`
* **验收**（断言，非「应该」）
  1. `encode → decode → encode` **定点**（逐字节相同），`decode(encode(j)) == j`，重放摘要相同。
  2. 归档与实时两条路径用同一把尺子：单签转换 `append_transition` → `NotSealed`，第三方签名 → `InvalidSignature`。
  3. 截断 JSON → `Encoding`；版本改成 2 → `InvalidVersion`；多一个字段 → `Encoding`（`deny_unknown_fields`）。
  4. 篡改条款价格 / 篡改签名 → `InvalidSignature`；调换或删除转换记录 → `InvalidKind`（相位链断）。
  5. 跨会话消息、重复消息 → `InvalidKind`。
  6. 归档文本里**没有** `phase` 字段：推导状态不可被单独篡改。
* **证据**（v1.2.3 实测）
  * 命令：`cargo test -p au4a-negotiate`；结果：**exit=0，40 passed / 0 failed / 0 warning**
    （25 单元 + 4 `tests/journal.rs` + 6 `tests/messages.rs` + 5 `tests/state_machine.rs`）；日志 `E:\DS\_forangent\logs\1.2-v1.2.3.log`。
  * 等级：`cpu-proto`。真实：规范 JSON 定点编码、SHA-256 内容寻址、Ed25519 逐条重验签。
    原型：归档停留在内存字符串层面，没有真实存储后端（本轨道按 brief 禁止文件 I/O，这也是可重放性的前提）。
  * 修复记录：首轮 2 个测试失败（`Envelope` 只有 `PartialEq` 不能 derive `Eq`；一处断言把迭代次数算错），
    另有 2 条 `unused_mut` warning，全部修掉后复跑全绿。
* **状态**：done

## v1.2.4 多轮协商

* **目标**：多轮报价/还价引擎：轮数上限、`REJECT` 不占额度、超限走**类型化拒绝**。
* **交付物**
  * `src/rounds.rs`：`Negotiation`（消息 + 状态机 + 归档三合一）、`Offer`、`Rejection`、`DEFAULT_MAX_ROUNDS = 6`。
  * `src/lib.rs`：`scenario` 改用协商引擎真跑（开局 → 还价 → 拒绝 → 还价），新增自检 `rounds.cap` / `rounds.reject_free`。
  * `tests/rounds.rs`：多轮协商经 PMB 真跑、超限与轮转违规的拒绝路径。
* **接口**：`Negotiation::{open,counter,accept,reject,archive,summary,price_trail,rounds_used}`、`DEFAULT_MAX_ROUNDS`
* **验收**（断言，非「应该」）
  1. `max_rounds=1`：第 2 次还价 → `Err(Overflow)`，同时内核记录 `PolicyDenied`；轮数、报价数、归档字节**全部不变**。
  2. 该拒绝码 `is_misconduct() == false`，`escalation_for == None`——额度耗尽不是恶意。
  3. 连续 6 次 `REJECT` 后 `rounds_used() == 0`，但每次仍留下一条**双方签名**的自环转换记录。
  4. 轮转规则：还价必须来自上一次报价的**对端**（自问自答 → `Err(InvalidKind)` + `Conflict`）；不能接受自己的报价。
  5. 七条消息全部经内核投递、逐条验签、`in_reply_to` 引用链连续（第 i 条引用第 i−1 条的 id）。
  6. 同种子两次独立协商的归档**逐字节相同**。
* **证据**（v1.2.4 实测）
  * 命令：`cargo test -p au4a-negotiate`；结果：**exit=0，51 passed / 0 failed / 0 warning**
    （32 单元 + 4 `tests/journal.rs` + 4 `tests/rounds.rs` + 6 `tests/messages.rs` + 5 `tests/state_machine.rs`）；日志 `E:\DS\_forangent\logs\1.2-v1.2.4.log`。
  * 真实行为：`150 →(b) 140 →(a) 130 →(b 拒绝) →(b) 125 →(a) 120 →(b 接受)`，4 轮额度、1 次拒绝。
  * 等级：`cpu-proto`（同前：密码学/状态机/归档真实；传输是同进程内存队列）。
  * 修复记录：首轮 3 个测试失败，全部由「轮转规则与场景脚本的真实交互」暴露（我最初让同一方连续还价、以及拒绝后由原作者还价），
    修正场景与断言后复跑全绿——规则是被测试逼出来的，不是拍脑袋写的。
* **状态**：done
