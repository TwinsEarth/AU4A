# 轨道 1.1 — Capability Graph 能力图

* **crate**：`crates/au4a-capgraph`
* **版本区间**：`v1.1.1 → v1.1.10`（严格串行，上一版没绿不开下一版）
* **依赖**：`au4a-core`（冻结基元）、`au4a-kernel`（宿主内核）、`serde`、`serde_json`。无新增外部 crate。
* **确定性**：库代码不读墙钟、不做文件/网络 I/O、无线程、无全局可变状态；时间只来自 `Kernel`/`LogicalClock`。

## 为什么做这条轨道

两个参考项目里都**没有能力图**：能力要么是一张扁平的白名单表（`nau-plugin` 的 21 个
`Capability`），要么是名片上的一段自我介绍（`AgentCard.skills`）。没有能力到能力的边，
没有衰减，没有格式兼容性，没有代价，也没有版本——于是「谁能接谁的活」只能由人读文档判断。

本轨道把能力做成 Agent 自己能读写的一份数据：**声明 → 广播 → 缓存 → 索引查询 → 路径规划 → 版本化**。

## v1.1.1 数据结构

**目标**：给「一条能力」一个可比较、可约束、可定价、可内容寻址的整数表示。

**交付物**

* `src/capability.rs`：`SkillId` / `FormatId`（Rust 与 JSON 两条路径都校验名字）、
  `Constraints`（`max_input_bytes` / `min_deadline_ms` / `max_concurrency` / `regions`）、
  `Capability`（skill / latency_p50_ms / latency_p99_ms / throughput_per_min / current_load_bp /
  price_per_unit / reliability_bp / supported_formats / produced_formats / constraints）。
* `src/lib.rs`：模块接入、真实自检、`results_json`、v1.1.1 版 `scenario`。
* `tests/data_structures.rs`：7 个集成测试。

**接口**

```rust
pub struct Capability {
    pub skill: SkillId,
    pub latency_p50_ms: u32,
    pub latency_p99_ms: u32,
    pub throughput_per_min: u32,
    pub current_load_bp: u16,        // 万分比 0..=10000
    pub price_per_unit: Credits,     // 整数微积分
    pub reliability_bp: u16,         // 万分比 0..=10000
    pub supported_formats: BTreeSet<FormatId>,
    pub produced_formats: BTreeSet<FormatId>,
    pub constraints: Constraints,
}
pub fn validate(&self) -> CoreResult<()>;
pub fn effective_latency_ms(&self) -> u64;      // p50 + (p99-p50)*load/10000
pub fn effective_reliability_bp(&self) -> u16;  // reliability*(10000-load)/10000
pub fn handoff_format(&self, next: &Capability) -> Option<FormatId>;
pub fn fingerprint(&self) -> CoreResult<String>; // SHA-256(规范 JSON)
```

**验收（全部为运行中的断言）**

1. 规范 JSON 里 9 个度量字段均为整数；`canonicalize` 对含浮点的值返回 `FloatForbidden`。
2. `p99 < p50`、`current_load_bp > 10000`、`reliability_bp > 10000`、空格式集合 → `validate()` 返回 `Err`。
3. `p50=100,p99=300,load=5000bp` → 加权延迟恰为 `200ms`、加权可靠度恰为 `4500bp`。
4. 同一能力两次构造得到同一 SHA-256 指纹；改价后指纹改变。
5. 产出 `{text/plain, application/json}` 与接受 `{application/json}` 可接续；与 `{audio/wav}` 不可接续。
6. `scenario` 两次运行返回**完全相同**的 JSON（可重放）。

## v1.1.2 声明 API

**目标**：能力进入图里只有一条合法路径——Agent 用自己的私钥签一份完整声明；替他人声明在构造阶段就被拒。

**交付物**

* `src/declaration.rs`：`Declaration`（`agent` / `epoch` / `issued_at` / `capabilities`，按技能名升序、拒绝重复技能）、
  `SignedDeclaration`（`verify()` 用 `Did::verify` 对规范 JSON 字节验签）。
* `src/graph.rs`：`AgentCapabilityGraph`（自己的声明进 `own`，别人的进邻居视图）、
  `CapGraphConfig`、`NeighborRecord`、`DeclareOutcome::{Applied, Unchanged, Rejected}`。
* `tests/declaration.rs`：8 个集成测试。

**接口**

```rust
pub struct Declaration { pub agent: Did, pub epoch: u64, pub issued_at: u64, pub capabilities: Vec<Capability> }
pub fn Declaration::new(agent, epoch, issued_at, caps) -> CoreResult<Declaration>;
pub fn Declaration::sign(self, keys: &AgentKeys) -> CoreResult<SignedDeclaration>; // 只能签自己
pub fn SignedDeclaration::verify(&self) -> CoreResult<()>;

pub struct AgentCapabilityGraph;
pub fn AgentCapabilityGraph::new(owner: Did, config: CapGraphConfig) -> Self;
pub fn AgentCapabilityGraph::apply(&mut self, signed: &SignedDeclaration, now: u64) -> DeclareOutcome;
pub fn AgentCapabilityGraph::capabilities_of(&self, did: &Did) -> Option<&[Capability]>;
```

**验收（运行中的断言）**

1. 自己的声明入图（`Applied`），重复同一份声明 4 次全部 `Unchanged`，`own_epoch` 不推进。
2. `B` 用自己私钥替 `A` 声明 → `Err(InvalidSignature)`；把已签声明里的 `agent` 换成 `B` → 图判 `unauthorized`。
3. 篡改已签声明的 `price_per_unit` / `throughput_per_min` → `unauthorized`（恶意码，一次即成立），邻居视图保持为空。
4. `epoch` 回退 → `stale_epoch`；同 `epoch` 异内容 → `conflict`；`epoch` 递增 → 接受且**完整替换**（声明是完整状态）。
5. 超过 `max_skills_per_agent` → `policy_denied`，且被拒声明不留痕（`capability_count()` 不变）。
6. 邻居声明不触碰自有状态；`skills()` 列出全部提供者且去重。

## v1.1.3 广播协议

**目标**：能力通告走全系统唯一的 Agent-to-Agent 信道 PMB（`Envelope`），真签名验签，篡改必被拒。

**交付物**

* `src/broadcast.rs`：`announce` / `announce_to` / `query_skill`（构造并封口信封）、
  `parse_announcement` / `parse_query`（唯一入图的门）、`ingest`（信封层 + 图声明层）、
  `pump`（消费内核队列：本轨道的入图，其他轨道的转发回队列）、`Ingest` / `PumpReport`。
* `src/lib.rs`：`demo_agents()`（5 个确定性角色）、`scenario` 改为真广播流程、4 条新自检。
* `tests/broadcast.rs`：10 个集成测试。

**接口**

```rust
pub const PROTOCOL: &str = "au4a.capgraph/1";
pub const KIND_ANNOUNCE: &str = "capgraph.announce";
pub const KIND_REQUEST: &str  = "capgraph.request";

pub fn announce(keys: &AgentKeys, declaration: &Declaration, ts: u64) -> CoreResult<Envelope>;
pub fn announce_to(keys, declaration, to: Did, ts, in_reply_to) -> CoreResult<Envelope>;
pub fn query_skill(keys, skill: &SkillId, ts, in_reply_to) -> CoreResult<Envelope>;
pub fn parse_announcement(env: &Envelope) -> Result<Announcement, (RefusalCode, String)>;
pub fn ingest(graph: &mut AgentCapabilityGraph, env: &Envelope, now: u64) -> Ingest;
pub fn pump(kernel: &mut Kernel, graph: &mut AgentCapabilityGraph, now: u64) -> PumpReport;
```

**验收（运行中的断言）**

1. `announce` 出的信封 `verify()` 通过、`to == None`（广播）、`kind == capgraph.announce`；
   4 字节大端分帧往返后信封完全相等、内容寻址 `id` 不变。
2. 改动 body 里的 `price_per_unit` / `throughput_per_min` / `reliability_bp` / `current_load_bp`
   任意一个 → `parse_announcement` 返回 `unauthorized`（`is_misconduct() == true`）。
3. `B` 用自己的私钥签信封、内部装 `A` 的合法声明：信封验签通过（真是 B 签的），
   但身份错配 → `unauthorized`，图不变（`capability_count() == 0`）。
4. 消息类型不对（`progress.event`）或协议版本不对（`au4a.capgraph/0`）→ `unsupported`，图不变。
5. 5 个 Agent 全量广播 → `pump` 报 `routed=4, applied=4, refused=0`，`known_agents=5`，
   且内核拒绝记录为空（合法流量不产生拒绝）。
6. `pump` 遇到他轨道信封（`safety.report`）→ `forwarded=1`，队列里那封信封的 `id` 不变；
   伪造通告时拒绝记在伪造者头上（`escalation_for == Quarantine` 指向伪造者，不指向被冒名者）。

## v1.1.4 缓存层

**目标**：邻居能力是有上限、会失效的缓存，而不是一张无限增长、永不陈旧的全局表。

**交付物**

* `src/cache.rs`：`CapabilityCache`（容量上限 + TTL 失效 + 确定性 LRU 淘汰 + 命中统计）、
  `CacheStats`、`CacheInsert`（报告被淘汰/被过期的 DID）。
* `src/graph.rs`：邻居侧改由缓存托管；新增 `get_neighbor` / `expire_neighbors` /
  `invalidate_neighbor` / `cache_stats` / `lru_order` / `live_neighbor_count`。
* `tests/cache.rs`：9 个集成测试。

**接口**

```rust
pub struct CapabilityCache;
pub fn CapabilityCache::new(capacity: usize, ttl_ticks: u64) -> Self; // capacity=0 → 不缓存
pub fn get(&mut self, did: &Did, now: u64) -> Option<&NeighborRecord>;   // 命中+触碰 LRU
pub fn insert(&mut self, record: NeighborRecord, now: u64) -> CacheInsert;
pub fn is_live(&self, did: &Did, now: u64) -> bool;
pub fn expire(&mut self, now: u64) -> Vec<Did>;      // 返回被清理者（DID 字典序）
pub fn evict_lru(&mut self) -> Option<Did>;
pub fn invalidate(&mut self, did: &Did) -> bool;
pub struct CacheStats { hits, misses, inserts, updates, evictions, expirations, invalidations }
```

**验收（运行中的断言）**

1. 容量 8 的缓存在 64 次写入过程中 `len()` 峰值 ≤ 8，末尾 `len()==8`，`evictions==56`；
   容量 3 时 `evictions==7`——上限是**硬**的。
2. 触碰 1、2 之后 LRU 顺序恰为 `[3, 1, 2]`，下一次写入淘汰 `3`；同一操作序列重跑得到同一淘汰结果。
3. TTL 用逻辑刻：`at=1000, ttl=20` 时第 1020 刻存活、第 1021 刻失效并计入 `expirations`；`ttl=0` 永不过期。
4. 图中邻居过期后被当作「没听过」：同 `epoch` 异内容不再判 `conflict`，而是重新接受（旧世界已不存在）。
5. 显式 `invalidate` 移除指定邻居且不动其它邻居；重复失效是空操作且不再计数。
6. 缓存容量配成 0 时返回 `resource_exhausted`，且该码**不是**恶意码（容量是竞争语义，不是作恶）。
7. 真实广播下容量 2 的图：4 条通告全部 `applied`，最终保留 2 条、淘汰 2 条，两个独立图的
   `lru_order()` 完全相同（可重放）。

## v1.1.5 查询接口

**目标**：「谁能做 X」只扫索引给出的候选，不扫全图；结果与朴素全扫**逐条一致**。

**交付物**

* `src/index.rs`：`CapabilityIndex`（`by_skill` / `by_input_format` 两张倒排表，键是 `(did, slot)` 而不是能力副本）、
  `CapabilityQuery`（10 个可选硬条件）、`CapabilityMatch`、`QueryStats`、`QueryResult`、`rank_and_truncate`。
* `src/graph.rs`：`query` / `best_for` / `providers_of` / `capability_at` / `index_consistent` /
  `index_summary`；索引在四个写入口（声明、淘汰、过期、失效）同步更新。
* `tests/query_index.rs`：8 个集成测试。

**接口**

```rust
pub fn AgentCapabilityGraph::query(&mut self, q: &CapabilityQuery, now: u64) -> QueryResult;
pub fn AgentCapabilityGraph::best_for(&mut self, skill: &SkillId, now: u64) -> QueryResult;
pub fn AgentCapabilityGraph::providers_of(&self, skill: &SkillId) -> Vec<Did>;
pub fn AgentCapabilityGraph::index_consistent(&self) -> bool;
pub struct QueryStats { pub candidates: usize, pub scanned: usize, pub matched: usize, pub nodes_total: usize }
```

**验收（运行中的断言）**

1. 视图含 200 条能力时，按技能查询 `candidates == scanned == 100`、`nodes_total == 200`——
   `scanned` 严格小于 `nodes_total`（未退化成全图扫描）。
2. 索引结果与「遍历全图逐个过滤」的集合**完全相同**（索引不是近似）。
3. `max_price` / `min_reliability_bp` / `max_latency_p99_ms` / `min_throughput` / `min_available_bp` /
   `region` / 输入输出格式 都是硬条件；过滤在候选集内完成（`scanned` 仍等于候选数）。
4. 输入格式过滤是**两张索引求交**：同一技能 2 条能力中，`application/json` 只命中 1 条（`candidates == 1`）。
5. 排序第一关键字是负载加权可靠度：`9000/9000/8000bp` 三条报价排序为 `5,5,4`，两次查询逐位相同。
6. 索引跟随缓存生命周期：淘汰、过期、显式失效后 `index_consistent() == true`，
   `index_summary()["entries"]` 与实际能力数一致；自有能力同样被索引。
7. 查不到 → `QueryResult::refusal_code() == Some(unsupported)`（类型化结局，非恶意、非异常）。
8. `scenario` 报告两次索引查询：`nodes_total=5`、translate 的 `scanned=2`（bob 与 dave 两个提供者）。
