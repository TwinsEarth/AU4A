# 轨道 1.8 — Cross-Chain Settlement 跨链结算

* **crate**：`crates/au4a-chain`
* **版本区间**：v1.8.1 → v1.8.10（10 个小版本，严格串行）
* **负责人**：track-economy
* **依赖**：`au4a-core`（冻结基元）、`au4a-kernel`（宿主内核）、`serde`、`serde_json`

## 最重要的一句话

**本轨道没有任何真实链上执行。** 所有「链上」都是[确定性测试网](#确定性测试网所有链上语义的唯一所在地)：
纯 CPU 状态机 + 内容寻址哈希 + 逻辑高度，不联网、不读墙钟、不碰文件。
链上证据等级恒为 `cpu-proto`，收据里的 `grade` 字段写死这个值、`real_network` 恒为 `false`——
**代码层面不可能把测试网结果冒充成真实链上成功**。

参考项目里 ERC-8004 / x402 / RGB / Taproot / Lightning **全部 0 命中**，所以这里是最容易造假的地方：
本轨道的做法是「把边界写进类型」，而不是写在文档的形容词里。

## 确定性测试网（所有「链上」语义的唯一所在地）

| 概念 | 实现 | 说明 |
|---|---|---|
| 链 | `ChainId::{BtcRegtest, EthLocal}` | 两条本地实例，各自独立的状态机与最终性深度 |
| 交易 | `ChainTx`（内容寻址 id） | 篡改任何字段 → id 不匹配 → `Malformed` |
| 防重放 | `applied` + `pending` 集合 | 同一 id 二次提交 → `Conflict` |
| 防乱序 | 每提交者 nonce 单调 | 回退 nonce → `StaleEpoch` |
| 出块 | `mine()` / `mine_to(height)` | 逻辑高度，确定性 |
| 最终性 | `finality_depth`（BTC 6 / ETH 12） | `is_final(height)`；未最终化的一切都**不算数** |
| 重组 | `reorg(depth)` | 超过最终性的重组被拒；被回滚交易重新可打包（nonce 同步重建） |
| 收据 | `Receipt { grade: cpu-proto, … }` | 「成功」只可能来自本地状态机 |
| 拒绝 | `ChainRefusal { op, code, detail }` | **一定带操作名**，并记进 `refusals` |

## 双轨守恒与 fail-closed

```text
桥出 bridge_out(X)：本地 可用 −X、锁定 +X（托管）  ｜ 链上表示 +X
桥回 bridge_in(X) ：链上表示 −X                  ｜ 本地 锁定 −X → 可用 +X
```

* 不变式 A：`Σ可用 + Σ锁定 + 罚没 == 发行`（账本侧，每次写路径后断言）；
* 不变式 B：`本地托管量 == 链上表示总量`（双轨侧）；
* **fail-closed**：`bridge::require_consistent()` 在不一致时返回 `Err`（映射为 `CoreError::InvalidKind`，
  因为 `CoreError` 是冻结枚举、没有 `Conflict` 变体），**账本永远是真相**——链上数字只用于对比，
  绝不用于「纠正」账本；不一致时拒绝结算而不是猜测。

## v1.8.1 RGB 集成

**目标**：把 RGB 的**客户端验证**语义做成确定性测试网适配器：创世发行 → 密封转移 → 客户端验证 →
最终化；并把「本地积分 ↔ 链上表示」的双轨守恒与 fail-closed 对账落地。

**交付物**

* `src/testnet.rs`：`ChainId`、`ChainTx`、`Block`、`Receipt`、`Testnet`
  （`accept` / `mine` / `mine_to` / `finality` / `reorg` / `rebuild_nonces`）、
  `ChainRefusal`、`RefusalSpec`、`ONCHAIN_GRADE`。
* `src/bridge.rs`：`BridgeBook`（`bridge_out` / `bridge_in` / `require_consistent` /
  `force_chain_supply` 故障注入）、`Reconciliation`、`reconcile`。
* `src/rgb.rs`：`Seal`、`RgbContract`（`issue` / `circulating` / `check_supply_conservation`）、
  `TransferBundle`（`new` / `verify` / `commitment`）、`RgbAdapter`
  （`issue` / `transfer` / `verify_bundle` / `finalize`）、`RGB_SUPPORTED`、`RGB_REFUSALS`。
* `src/lib.rs`：自检 5 项（证据等级 / 具名拒绝 / 双轨守恒 / fail-closed / 接线）+ 场景。

**RGB 具名拒绝清单（`RGB_REFUSALS`，按名字拒绝 + `RefusalCode`）**

| 操作 | 拒绝码 | 原因 |
|---|---|---|
| `rgb.atomic_swap` | `unsupported` | 原子交换需要 HTLC/哈希时间锁语义，本原型未实现 |
| `rgb.lightning_route` | `unsupported` | 闪电网络路由需要真实 P2P 与通道状态，本轨道不联网 |
| `rgb.unanchored_issuance` | `policy_denied` | 无锚增发会破坏总量守恒，策略上永久拒绝 |
| `rgb.consensus_bridge` | `unsupported` | 共识层桥接需要真实 BTC 节点与 SPV 证明，只做语义原型 |
| `rgb.blind_unsealed` | `malformed` | 未带致盲因子的转移包不可验证 |
| 其他任何未知 op | `unsupported` | 按名字拒绝，detail 里列出已知清单 |

**验收（25 个断言全绿）**

* `issuing_creates_a_content_addressed_asset_with_conserved_supply`：资产 id 64 位 hex、
  流通量 == 发行量；第二次发行 → `Conflict`。
* `a_sealed_transfer_moves_value_and_conserves_the_supply`：400 → 250/150，
  输入封印变花、流通量仍 400。
* `a_tampered_bundle_is_refused`：改输出金额不改承诺 → `Malformed`（detail 含「承诺」），
  且拒绝被记录（`refusals == 1`）。
* `double_spending_a_seal_is_refused`：同一封印二次花费 → `Conflict`（detail 含「双花」）。
* `a_bundle_whose_inputs_do_not_match_its_outputs_is_refused`：Σ输入 1000 ≠ Σ输出 999 → `Malformed`。
* `finalizing_before_finality_is_refused_and_succeeds_afterwards`：未达最终性 → `Timeout`；
  叠够深度后成功；重复最终化 → `Conflict`。
* `unsupported_operations_are_refused_by_name`：5 个具名拒绝逐个断言 `op` 与 `code`，
  且 `refusals == 5`（一个都没被静默吞掉）。
* `replaying_the_same_transfer_transaction_is_refused`：同 id 重放 → `Conflict`。
* `the_local_escrow_and_the_rgb_supply_are_the_same_number`：本地托管 == 链上表示 == RGB 流通量。
* 测试网侧：篡改 → `Malformed`、跨链 → `Malformed`、重放 → `Conflict`、乱序 nonce → `StaleEpoch`、
  出块/最终性/确认数、`reorg` 受最终性约束、被回滚交易可重新打包、收据恒为 `cpu-proto`。

## v1.8.2 Taproot Assets

**目标**：把「资产承诺锚进一个 BTC 输出，链上只露输出键，细节由持有者用 Merkle 证明自证」
这套语义做成确定性测试网适配器。

**语义**

```text
叶子     = H(asset_id ‖ amount ‖ seal)
merkle   = 比特币式成对哈希（奇数复制最后一个）
输出键   = H(internal_key ‖ merkle_root)          // 简化版 BIP341 tweak
锚定     = taproot.anchor：一次锚定一个资产（重复锚定 → Conflict）
证明     = taproot.proof：为第 i 个叶子生成认证路径
验证     = taproot.verify：重算根 + 检查锚定交易已达最终性
```

**具名拒绝清单（`TAPROOT_REFUSALS`）**

| 操作 | 拒绝码 | 原因 |
|---|---|---|
| `taproot.script_path_spend` | `unsupported` | 脚本路径花费需要真实脚本树与见证，本原型只做键路径语义 |
| `taproot.schnorr_multisig` | `unsupported` | Schnorr 多签需要真实签名聚合，本轨道没有签名设备与网络 |
| `taproot.asset_inflation` | `policy_denied` | 增发会破坏总量守恒，策略上永久拒绝 |
| `taproot.offchain_swap` | `unsupported` | 链下互换需要真实对手方与超时脚本 |
| 其他未知 op | `unsupported` | 按名字拒绝，detail 列出已知清单 |

**运行时（非操作级）拒绝**：金额列表为空/含非正数 → `Malformed`；内部键非 64 位 hex → `Malformed`；
叶子下标越界 → `Malformed`；锚定未达最终性就验证 → `Timeout`；证明不成立 → `Malformed`。

**交付物**：`src/taproot.rs`（`ProofStep`、`leaf_hash`、`merkle_root`、`merkle_proof`、`verify_merkle`、
`TaprootAnchor`、`TaprootAdapter`、`TAPROOT_SUPPORTED`、`TAPROOT_REFUSALS`）；
`src/lib.rs` 新增自检 `taproot.merkle` 与场景 `taproot` 段。

**验收（33 个断言全绿）**

* `anchoring_derives_a_deterministic_output_key_and_conserves_the_total`：250+150 → 总额 400、
  2 个叶子、输出键 == 重新派生的输出键、Merkle 根可重算。
* `merkle_proofs_verify_and_tampering_breaks_them`：5 个叶子的每条路径都成立；
  换叶子 → 不成立；篡改路径 → 不成立；越界下标 → `InvalidKind`。
* `a_proof_verifies_end_to_end_only_after_finality`：未达最终性 → `Timeout`；叠够深度 → 通过。
* `a_tampered_leaf_is_refused_by_the_verifier`：伪造叶子 → `Malformed`（detail 含「证明不成立」）。
* `anchoring_the_same_asset_twice_is_refused`：→ `Conflict`，锚定数仍为 1。
* `degenerate_anchors_are_refused`：空金额 / 内部键长度错 → `Malformed`，锚定数为 0。
* `named_refusals_cover_the_taproot_unsupported_set`：5 个具名拒绝逐个断言 op 与 code，`refusals == 5`。
* `the_taproot_rail_matches_the_local_escrow`：本地托管 400 == Taproot 锚定总量 400，对账通过。

| 等级 | `cpu-proto`（无 BIP341 真实 tweak、无真实签名、无 BTC 节点；Merkle 为真实哈希运算） |
| 快照 | `_forangent\snapshots\v1.8.2\` |

**状态**：done
