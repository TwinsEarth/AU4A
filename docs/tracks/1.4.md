# 轨道 1.4 — Economic Autonomy 经济自主

* **crate**：`crates/au4a-economy`
* **版本区间**：v1.4.1 → v1.4.10（10 个小版本，严格串行）
* **负责人**：track-economy
* **依赖**：`au4a-core`（冻结基元）、`au4a-kernel`（宿主内核）、`serde`、`serde_json`
* **人类的位置**：人类只能看三个只读投影（进度 / 结果 / 收益），**不能**发起、批准、定价、裁决。
  本轨道不提供任何写路径给人类。

## 贯穿全轨道的三条不变式

1. **账本守恒**：一切账务走 `au4a_core::Ledger`，每个写路径末尾调用
   `check_conservation()`：`Σ可用 + Σ锁定 + 罚没 == 已发行`。
2. **整数经济**：金额只用 `Credits`（微积分），比率只用基点（1 bp = 0.01%）。
   库代码不含浮点，规范 JSON 直接拒绝浮点，所以同输入必然同输出、可重放。
3. **证据闸门**：`EvidenceGrade::Unverified` 永远不可结算（由 `Kernel::settle` 强制）；
   `CpuProto` 只能结算不超过 `KernelConfig::cpu_proto_settle_cap` 的金额。
   真实链上执行属于 **v1.8**，本轨道只做**兑换路由决策与账务**，绝不伪造链上成功。

## v1.4.1 余额管理

**目标**：让每个 Agent 自己申报并执行余额策略（运营底线 / 目标质押比例 / 单笔支出上限），
拒绝路径与执行路径分离，任何拒绝都不改动账本一个字节。

**交付物**

* `src/balance.rs`：`BalancePolicy`、`SpendVerdict`、`check_spend`、`spend`、`autostake`、
  `spendable`、`stake_target`、`stake_deficit`、`delta`、`BalanceReport`、`BalanceManager`。
* `src/lib.rs`：`self_check()` 真实跑两条余额自检；`scenario()` 在共享内核上跑通
  「注册 → 自主申报策略 → 支付 → 被拒绝 → 自主质押 → 守恒断言」。

**接口（本版新增 public 项）**

```rust
pub struct BalancePolicy { pub reserve_floor: Credits, pub stake_target_bp: i64, pub max_spend_bp: i64 }
pub enum SpendVerdict { Allow, ZeroAmount, BelowReserve, OverSingleCap }
pub fn check_spend(ledger: &Ledger, who: &Did, amount: Credits, policy: &BalancePolicy) -> CoreResult<SpendVerdict>
pub fn spend(ledger: &mut Ledger, from: &Did, to: &Did, amount: Credits, policy: &BalancePolicy) -> CoreResult<Credits>
pub fn autostake(ledger: &mut Ledger, who: &Did, policy: &BalancePolicy, budget: Credits) -> CoreResult<Credits>
pub fn spendable(ledger: &Ledger, who: &Did, policy: &BalancePolicy) -> CoreResult<Credits>
pub fn stake_target / stake_deficit(ledger: &Ledger, who: &Did, policy: &BalancePolicy) -> CoreResult<Credits>
pub fn delta(before: &Account, after: &Account) -> AccountDelta
pub fn assert_conserved(ledger: &Ledger) -> CoreResult<()>
pub struct BalanceManager { /* 每个 Agent 只申报自己的策略；无「替别人设定」的方法 */ }
```

**判定表（纯函数 `check_spend`，顺序即优先级）**

| 条件 | 判定 | 写路径动作 |
|---|---|---|
| `amount == 0` | `zero_amount` | 返回 `CoreError::ZeroAmount`，账本不变 |
| `available < reserve_floor + amount` | `below_reserve` | 返回 `CoreError::InsufficientFunds`，账本不变 |
| `amount > available × max_spend_bp / 10000` | `over_single_cap` | 返回 `CoreError::InsufficientFunds`，账本不变 |
| 其余 | `allow` | `transfer` → `check_conservation()` |

越界参数（基点 < 0 或 > 10000）在申报策略时即被拒绝：负数 → `NegativeAmount`，
越界 → `InvalidKind`（`CoreError` 是冻结枚举，没有 `OutOfRange`，映射固定且已写入文档）。

**验收**

* `an_allowed_spend_moves_exactly_the_amount`：断言支付 300 后 a 可用 700、b 可用 300、守恒成立。
* `a_spend_that_would_break_the_reserve_floor_is_refused_and_changes_nothing`：
  可用 400 / 底线 100 时支出 301 被拒，拒绝后双方余额与拒绝前逐字节相同。
* `the_single_transaction_cap_is_enforced`：可用 10 000、`max_spend_bp=1000` 时
  1 001 被拒、1 000 通过。
* `autostake_locks_up_to_the_target_and_never_crosses_the_floor`：目标 = 总资产 × 20%，
  达标后再次补足返回 `ZeroAmount`（不静默成功）。
* `conservation_holds_across_a_scripted_sequence`：支付 / 质押 / 转移 / 罚没 6 步，
  每步后 `check_conservation()` 成立，最后罚没精确等于锁定余额。

## v1.4.2 定价策略

**目标**：Agent 用**自己**的信誉分 / 能力稀缺度 / 当前负载算出报价并广播，买方在共享内核里
「发现彼此」并按整数单价挑选供给方。全程整数基点运算，无浮点，同输入必然同输出。

**定价公式（[`pricing::quote`]，纯函数）**

```text
信誉折扣   = reputation_bp × reputation_discount_max_bp / 10000      （向下取整）
稀缺溢价   = scarcity_bp   × scarcity_premium_max_bp   / 10000
负载溢价   = load_bp       × load_premium_max_bp       / 10000
multiplier = clamp(10000 + 负载溢价 + 稀缺溢价 − 信誉折扣, min_bp, max_bp)
unit_price = max(base_price × multiplier / 10000, 1)
```

默认系数：信誉最多降 20%、稀缺最多加 30%、负载最多加 50%，总乘数夹在 `[5000, 20000]` bp。
价格下限为 1 微积分，报价绝不会塌缩成 0（0 额结算在账本层是非法调用）。

**交付物**

* `src/pricing.rs`：`PriceInputs`、`PriceKnobs`、`PriceComponents`、`PriceQuote`
  （`total_for` / `fingerprint`）、`quote`、`unit_price`。
* `src/lib.rs`：`PRICE_KIND = "economy.price"` 公告类型；场景新增「两个供给方各自定价 →
  签名广播 → 买方 `drain` 验签 → 按 `(unit_price, provider)` 升序取最便宜者」。
* `self_check()` 新增 `pricing.reproducible`（两次报价与内容哈希一致 + 钉住具体数值）
  与 `pricing.monotonicity`（0→10000 扫描负载与信誉）。

**接口（本版新增 public 项）**

```rust
pub struct PriceInputs { pub base_price: Credits, pub reputation_bp: i64, pub scarcity_bp: i64, pub load_bp: i64 }
pub struct PriceKnobs { /* 5 个基点系数，DEFAULT 常量 */ }
pub struct PriceComponents { pub reputation_discount_bp: i64, pub scarcity_premium_bp: i64, pub load_premium_bp: i64 }
pub struct PriceQuote { pub inputs, pub components, pub multiplier_bp: i64, pub unit_price: Credits }
pub fn quote(inputs: &PriceInputs, knobs: &PriceKnobs) -> CoreResult<PriceQuote>
pub fn unit_price(inputs: &PriceInputs, knobs: &PriceKnobs) -> CoreResult<Credits>
pub const PRICE_KIND: &str = "economy.price";
```

**验收**

* `concrete_numbers_are_pinned`：base 1 000 000、信誉 8000、稀缺 2000、负载 4000 →
  折扣 1600 / 稀缺 600 / 负载 2000 / 乘数 11000 / 单价 **1 100 000**（逐项断言）。
* `the_same_input_always_gives_the_same_quote` + `the_quote_is_integer_only_and_canonicalizable`：
  两次报价相等、内容哈希相等，且报价能通过「拒绝浮点」的规范 JSON 编码。
* `load_up_price_up_never_down`：`load_bp` 从 0 扫到 10000 逐点断言价格不降；
  500bp 网格上断言**严格**递增。
* `reputation_up_price_down_never_up`：信誉 0→10000 逐点断言价格不升；500bp 网格严格递减。
* `scarcity_up_price_up`：稀缺度每 +500bp 价格严格上升。
* `clamps_bound_the_multiplier_on_both_ends`：`[9500, 12000]` 夹取在两端都生效。
* `a_price_never_collapses_to_zero`：base 1、满信誉 → 乘数 8000、单价仍为 1。
* `degenerate_inputs_are_refused`：base 0 → `ZeroAmount`；信誉 10001 → `InvalidKind`；
  负数 → `NegativeAmount`；`min > max` → `InvalidKind`。
