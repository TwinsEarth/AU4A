# 轨道 1.5 — Safety API 安全 API（`au4a-safety`）

`v1.5.1 → v1.5.10` ｜ 中版本标题：**Safety API 安全 API** ｜ 负责：track-safety

安全接口是 **Agent 侧**的，不是人类控制台：Agent 自己查权限边界、自己举报（带可验证证据哈希）、
自己被处罚后自己提交申诉证据、自己查处罚记录、自己按案件订阅状态变更。
本 crate 里**没有**审批入口、管理员身份或人工复核阶段——「等人类批准」在这里是不可表达的状态。

## 0. 三条不可协商的不变式

| 不变式 | 语义 | 落地方式 |
|---|---|---|
| **无罪不罚** | 未被裁决确认的举报不改变任何 Agent 的余额与信誉 | 举报只写哈希链事件；账本改动只发生在带仲裁者签名的裁决被接受时（测试断言余额逐字段不变） |
| **证据可验证** | 举报与申诉必须携带可复算的证据哈希 | `EvidenceRef::commit` 用 `canonical_hash` 计算，`verify` 复算；缺失/伪造一律拒绝 |
| **状态可审计** | 每次状态变更写入哈希链事件 `prev + 内容 → hash` | 单链追加；断链、乱序、哈希不符均可检测（`v1.5.10` 审计） |

## 1. 依赖与边界

* 只依赖 `au4a-core`（冻结基元）+ `au4a-kernel`（宿主内核）+ `serde` / `serde_json`。
* **不依赖** `au4a-council`：与仲裁的协作只走**数据契约**（可序列化 JSON，见 v1.5.7）。
* 库代码不读墙钟、不做文件/网络 I/O、无全局可变状态：时间是 `Kernel` 的逻辑时钟。
* 人类观察层只能读 `Kernel::observe()`（只读投影），本 crate 不提供任何人类写路径。

## v1.5.1 权限查询

**目标**：Agent 能查询自己的**权限边界**，且边界是结构化的（允许 / 禁止 / 需质押），不是自由文本。

**交付物**

* `src/config.rs`：`SafetyConfig { service, arbiters }` + 仲裁者信任闸门 `require_arbiter`。
* `src/permission.rs`：`Permission`（8 个权限点）、`DenialReason`（4 个结构化拒绝码）、
  `PermissionBoundary { did, registered, allowed, denied, stake_gates }`、`PermissionQuery`、
  `stake_requirement`、`query_permissions`。
* `src/setup.rs`：确定性身份装配（轨道前缀种子，避免与其它轨道撞 DID；`ensure_agent` 幂等）。
* `src/lib.rs`：`self_check()`（跑真实流程后的断言）、`results_json()`、`scenario()`。

**接口**

```rust
pub enum Permission { Register, SendMessage, QuerySafety, ReportViolation,
                      AppealPenalty, SubscribeCase, Settle, IssueVerdict }
pub enum DenialReason { AlreadyRegistered, NotRegistered,
                        StakeBelowMinimum { required: Credits, actual: Credits }, ArbiterOnly }
pub struct PermissionBoundary { pub did: Did, pub registered: bool,
    pub allowed: Vec<Permission>, pub denied: Vec<DeniedPermission>,
    pub stake_gates: Vec<StakeGate> }
impl PermissionBoundary {
    pub fn of(kernel: &Kernel, config: &SafetyConfig, did: &Did) -> Self;
    pub fn allows(&self, p: Permission) -> bool;
    pub fn denial(&self, p: Permission) -> Option<&DenialReason>;
    pub fn to_json(&self) -> CoreResult<Value>;   // 以及 from_json
}
pub fn stake_requirement(p: Permission, min_stake: Credits) -> Credits;
```

**判定规则（全部由公开状态推导，任何 Agent 都能复算）**

1. 未注册：只有 `Register` 可达，其余全部 `not_registered`。
2. 已注册：`IssueVerdict` 只有 `SafetyConfig::arbiters` 名单内的 DID 可达，其余得到 `arbiter_only`；
   `Register` 得到 `already_registered`。
3. 质押门槛：`Register` 走「余额为零则由创世额度资助」的**真实内核语义**；
   其余需要质押的权限看**锁定质押**是否 ≥ `kernel.config().min_stake`。
   罚没把锁定质押打到下限以下时，举报权立刻以 `stake_below_minimum { required, actual }` 被收回。
4. 查询与订阅**免费**（`required = 0`）：读自己的权利不被余额挡住。

**验收（`src/permission.rs` / `src/config.rs` 内联测试 14 个）**

* 已注册 Agent：6 个权限可达、`Register → already_registered`、`IssueVerdict → arbiter_only`。
* 未注册 DID：`allowed == [Register]`，其余 7 个全部 `not_registered`；创世额度使注册门槛可见且满足。
* 有余额但低于质押下限的 DID：注册被 `stake_below_minimum { required: 10, actual: 3 }` 拒绝。
* 罚没清零锁定质押后：`ReportViolation` 被拒、`QuerySafety` 仍可达。
* JSON 结构化：`denied[i].reason.code` ∈ {already_registered, not_registered, stake_below_minimum, arbiter_only}，
  `allowed + denied == 8`；`from_json(to_json(x)) == x`。
* 权限名 8 个、唯一、可往返解析；同一状态的两次查询字节相同。

**证据**：`cargo test -p au4a-safety` → **14 passed / 0 failed / 0 warning**（2026-10-04 本机 Windows，`CARGO_TARGET_DIR=E:\DS\_forangent\target\au4a-safety`，log `_forangent\logs\1.5-v1.5.1.log`）。
等级 `verified`（本机真实执行）。

**状态**：done（快照 `_forangent\snapshots\v1.5.1`）。

## v1.5.2 违规举报

**目标**：Agent 举报其他 Agent 的违规行为，必须携带**可复算**的证据哈希；
未确认的举报**不改变任何 Agent 的余额与信誉**。

**交付物**

* `src/evidence.rs`：`EvidenceKind`（4 种）、`EvidenceRef`（承诺 + 复算 + 成形检查）、
  `require_well_formed`（证据组：非空且逐个成形）。
* `src/chain.rs`：`SafetyEvent`（`prev` + 内容 → `hash`）、`SafetyEventKind`（6 种）、
  `verify_chain`、`ChainVerdict`、`ChainBreak`（三类可区分断裂）、`GENESIS_PREV`（64 个 0）。
* `src/case.rs`：`ViolationKind`（6 种）、`CaseStatus`（4 种）、`ViolationReport`（举报人签名 + 内容寻址）、`Case`。
* `src/office.rs`：`SafetyOffice`（服务密钥 = 配置里的服务 DID）、`report`、`append`、
  `ledger_snapshot` / `ledger_fingerprint`（账本投影）。

**接口**

```rust
pub struct EvidenceRef { pub kind: EvidenceKind, pub digest: String }
impl EvidenceRef {
    pub fn commit(kind: EvidenceKind, payload: &Value) -> CoreResult<Self>;
    pub fn commit_bytes(kind: EvidenceKind, bytes: &[u8]) -> Self;
    pub fn verify(&self, payload: &Value) -> CoreResult<()>;
    pub fn is_well_formed(&self) -> bool;
}
pub struct SafetyEvent { pub seq: u64, pub at: u64, pub kind: SafetyEventKind,
                         pub payload: Value, pub prev: String, pub hash: String }
pub fn verify_chain(events: &[SafetyEvent]) -> ChainVerdict;
pub struct SafetyOffice { /* config, service, events, cases */ }
impl SafetyOffice {
    pub fn new(config: SafetyConfig, service: AgentKeys) -> CoreResult<Self>;
    pub fn report(&mut self, kernel: &mut Kernel, keys: &AgentKeys, subject: &Did,
                  violation: ViolationKind, evidence: EvidenceRef,
                  payload: &Value) -> CoreResult<ViolationReport>;
    pub fn verify_chain(&self) -> ChainVerdict;
}
```

**证据闸门与拒绝码（结构化；`CoreError` 变体是冻结集合，不可能为每种语义新增变体）**

| 情形 | `CoreError` | `RefusalCode` |
|---|---|---|
| 举报者未注册 | `UnknownAgent` | `unauthorized` |
| 举报自己 | `InvalidKind` | `policy_denied` |
| 主体未注册 | `UnknownAgent` | `stale_epoch` |
| 证据摘要缺失/不成形 | `InvalidSignature` | `policy_denied` |
| 证据本体缺失（无法复算） | `Encoding` | `policy_denied` |
| 摘要与本体不一致（伪造） | `InvalidSignature` | `policy_denied` |

**为什么无罪不罚是结构性的**：`report()` 路径上没有任何账本/名片写调用，
罚没只可能来自带仲裁者签名的裁决（v1.5.4 / v1.5.7）。因此「未确认的举报改变余额」
不是被纪律禁止，而是**不可达**。

**验收（新增 30 个测试，累计 44 个）**

* 举报后案件为 `reported`，事件链 1 条且 `verify_chain` 通过，链头 64 位 hex。
* 举报前后账本快照（逐账户可用/锁定 + 全局发行/罚没）与双边 `AgentCard` **逐字段相等**；
  `slashed == 0`；守恒式成立。
* 伪造摘要：`InvalidSignature`，案件数 0、事件数 0、账本不变，拒绝原因含 "does not match"。
* 缺失证据（摘要空串 / 本体为 `null`）：分别得 `InvalidSignature` / `Encoding`。
* 自举报 → `InvalidKind`；未知主体 → `UnknownAgent`（拒绝码 `stale_epoch`）；未注册举报者 → `Unauthorized`。
* 连续两次举报：事件 2 条，`events[1].prev == events[0].hash`，链完好。
* 链篡改（副本）：内容篡改 → `hash_mismatch@0`；删除一条 → `seq_mismatch@1`；改写前驱 → `prev_mismatch@1`；
  伪造 hash → `hash_mismatch@1`；空链 → ok、链头为创世前驱。
* 服务身份与配置不一致 → `InvalidSignature`；账本快照与输入顺序无关（排序后指纹相同）。

**证据**：`cargo test -p au4a-safety` → **44 passed / 0 failed / 0 warning**（2026-10-04 本机 Windows，
log `_forangent\logs\1.5-v1.5.2.log`）。等级 `verified`。

**状态**：done（快照 `_forangent\snapshots\v1.5.2`）。

## v1.5.3 申诉提交（计划）

`Appeal`（必须由案件主体本人签名）、状态机 `REPORTED → APPEALED`；申诉本身不动账本。

## v1.5.4 处罚查询（计划）

`SanctionKind`、`PenaltyOrder`（仲裁者签名的数据契约）、`PenaltyRecord`、`penalties_for`；
罚没受锁定余额约束、守恒仍成立。

## v1.5.5 通知机制（计划）

`Subscription`（按案件 + 状态集合）、`Notification`、订阅/退订（仅本人可退订）、
订阅即刻回放当前状态快照，此后只投递增量。

## v1.5.6 PMB 扩展（计划）

`SAFETY_QUERY` / `SAFETY_REPORT` / `SAFETY_APPEAL` 三种消息类型（`Envelope` 真签名 + 线格式往返）、
`safety.receipt` 回执、`SafetyOffice::handle` 服务侧分发。

## v1.5.7 仲裁接入（计划）

`ArbitrationRequest` / `ArbitrationVerdict` 数据契约（不依赖 `au4a-council` crate），
`REJECTED` 时回滚罚没（归还），`ARBITRATED` 终局状态与通知。

## v1.5.8 测试（计划）

`tests/` 端到端 + 对抗用例（伪造裁决、第三方申诉、链篡改）+ `scenario` 确定性重放。

## v1.5.9 文档（计划）

`schema_json()` 机器可读契约导出 + 本文档与 `1.5.json` 定稿（线格式、错误映射表、证据分级）。

## v1.5.10 审计（计划）

`AuditReport` / `AuditFinding`：链完整性、**状态 == 重放(事件链)**、账本罚没与处罚记录交叉核对。
