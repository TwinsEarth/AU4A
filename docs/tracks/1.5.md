# 轨道 1.5 — Safety API 安全 API（`au4a-safety`）

`v1.5.1 → v1.5.10` ｜ 中版本标题：**Safety API 安全 API** ｜ 负责：track-safety

安全接口是 **Agent 侧**的，不是人类控制台：Agent 自己查权限边界、自己举报（带可验证证据哈希）、
自己被处罚后自己提交申诉证据、自己查处罚记录、自己按案件订阅状态变更。
本 crate 里**没有**审批入口、管理员身份或人工复核阶段——「等人类批准」在这里是不可表达的状态。

## 0. 三条不可协商的不变式

| 不变式 | 语义 | 落地方式 |
|---|---|---|
| **无罪不罚** | 未被裁决确认的举报不改变任何 Agent 的余额与信誉 | 举报只写哈希链事件；账本改动只发生在带仲裁者签名的裁决被接受时（测试断言余额逐字段不变） |
| **证据可验证** | 举报与申诉必须携带可复算的证据哈希 | `EvidenceRef::commit` 用 `canonical_hash` 计算，`verify` 复算；缺失/伪造一律拒绝 |
| **状态可审计** | 每次状态变更写入哈希链事件 `prev + 内容 → hash` | 单链追加；断链、乱序、哈希不符均可检测（`v1.5.10` 审计） |

## 1. 依赖与边界

* 只依赖 `au4a-core`（冻结基元）+ `au4a-kernel`（宿主内核）+ `serde` / `serde_json`。
* **不依赖** `au4a-council`：与仲裁的协作只走**数据契约**（可序列化 JSON，见 v1.5.7）。
* 库代码不读墙钟、不做文件/网络 I/O、无全局可变状态：时间是 `Kernel` 的逻辑时钟。
* 人类观察层只能读 `Kernel::observe()`（只读投影），本 crate 不提供任何人类写路径。

## v1.5.1 权限查询

**目标**：Agent 能查询自己的**权限边界**，且边界是结构化的（允许 / 禁止 / 需质押），不是自由文本。

**交付物**

* `src/config.rs`：`SafetyConfig { service, arbiters }` + 仲裁者信任闸门 `require_arbiter`。
* `src/permission.rs`：`Permission`（8 个权限点）、`DenialReason`（4 个结构化拒绝码）、
  `PermissionBoundary { did, registered, allowed, denied, stake_gates }`、`PermissionQuery`、
  `stake_requirement`、`query_permissions`。
* `src/setup.rs`：确定性身份装配（轨道前缀种子，避免与其它轨道撞 DID；`ensure_agent` 幂等）。
* `src/lib.rs`：`self_check()`（跑真实流程后的断言）、`results_json()`、`scenario()`。

**接口**

```rust
pub enum Permission { Register, SendMessage, QuerySafety, ReportViolation,
                      AppealPenalty, SubscribeCase, Settle, IssueVerdict }
pub enum DenialReason { AlreadyRegistered, NotRegistered,
                        StakeBelowMinimum { required: Credits, actual: Credits }, ArbiterOnly }
pub struct PermissionBoundary { pub did: Did, pub registered: bool,
    pub allowed: Vec<Permission>, pub denied: Vec<DeniedPermission>,
    pub stake_gates: Vec<StakeGate> }
impl PermissionBoundary {
    pub fn of(kernel: &Kernel, config: &SafetyConfig, did: &Did) -> Self;
    pub fn allows(&self, p: Permission) -> bool;
    pub fn denial(&self, p: Permission) -> Option<&DenialReason>;
    pub fn to_json(&self) -> CoreResult<Value>;   // 以及 from_json
}
pub fn stake_requirement(p: Permission, min_stake: Credits) -> Credits;
```

**判定规则（全部由公开状态推导，任何 Agent 都能复算）**

1. 未注册：只有 `Register` 可达，其余全部 `not_registered`。
2. 已注册：`IssueVerdict` 只有 `SafetyConfig::arbiters` 名单内的 DID 可达，其余得到 `arbiter_only`；
   `Register` 得到 `already_registered`。
3. 质押门槛：`Register` 走「余额为零则由创世额度资助」的**真实内核语义**；
   其余需要质押的权限看**锁定质押**是否 ≥ `kernel.config().min_stake`。
   罚没把锁定质押打到下限以下时，举报权立刻以 `stake_below_minimum { required, actual }` 被收回。
4. 查询与订阅**免费**（`required = 0`）：读自己的权利不被余额挡住。

**验收（`src/permission.rs` / `src/config.rs` 内联测试 14 个）**

* 已注册 Agent：6 个权限可达、`Register → already_registered`、`IssueVerdict → arbiter_only`。
* 未注册 DID：`allowed == [Register]`，其余 7 个全部 `not_registered`；创世额度使注册门槛可见且满足。
* 有余额但低于质押下限的 DID：注册被 `stake_below_minimum { required: 10, actual: 3 }` 拒绝。
* 罚没清零锁定质押后：`ReportViolation` 被拒、`QuerySafety` 仍可达。
* JSON 结构化：`denied[i].reason.code` ∈ {already_registered, not_registered, stake_below_minimum, arbiter_only}，
  `allowed + denied == 8`；`from_json(to_json(x)) == x`。
* 权限名 8 个、唯一、可往返解析；同一状态的两次查询字节相同。

**证据**：`cargo test -p au4a-safety` → **14 passed / 0 failed / 0 warning**（2026-10-04 本机 Windows，`CARGO_TARGET_DIR=E:\DS\_forangent\target\au4a-safety`，log `_forangent\logs\1.5-v1.5.1.log`）。
等级 `verified`（本机真实执行）。

**状态**：done（快照 `_forangent\snapshots\v1.5.1`）。

## v1.5.2 违规举报

**目标**：Agent 举报其他 Agent 的违规行为，必须携带**可复算**的证据哈希；
未确认的举报**不改变任何 Agent 的余额与信誉**。

**交付物**

* `src/evidence.rs`：`EvidenceKind`（4 种）、`EvidenceRef`（承诺 + 复算 + 成形检查）、
  `require_well_formed`（证据组：非空且逐个成形）。
* `src/chain.rs`：`SafetyEvent`（`prev` + 内容 → `hash`）、`SafetyEventKind`（6 种）、
  `verify_chain`、`ChainVerdict`、`ChainBreak`（三类可区分断裂）、`GENESIS_PREV`（64 个 0）。
* `src/case.rs`：`ViolationKind`（6 种）、`CaseStatus`（4 种）、`ViolationReport`（举报人签名 + 内容寻址）、`Case`。
* `src/office.rs`：`SafetyOffice`（服务密钥 = 配置里的服务 DID）、`report`、`append`、
  `ledger_snapshot` / `ledger_fingerprint`（账本投影）。

**接口**

```rust
pub struct EvidenceRef { pub kind: EvidenceKind, pub digest: String }
impl EvidenceRef {
    pub fn commit(kind: EvidenceKind, payload: &Value) -> CoreResult<Self>;
    pub fn commit_bytes(kind: EvidenceKind, bytes: &[u8]) -> Self;
    pub fn verify(&self, payload: &Value) -> CoreResult<()>;
    pub fn is_well_formed(&self) -> bool;
}
pub struct SafetyEvent { pub seq: u64, pub at: u64, pub kind: SafetyEventKind,
                         pub payload: Value, pub prev: String, pub hash: String }
pub fn verify_chain(events: &[SafetyEvent]) -> ChainVerdict;
pub struct SafetyOffice { /* config, service, events, cases */ }
impl SafetyOffice {
    pub fn new(config: SafetyConfig, service: AgentKeys) -> CoreResult<Self>;
    pub fn report(&mut self, kernel: &mut Kernel, keys: &AgentKeys, subject: &Did,
                  violation: ViolationKind, evidence: EvidenceRef,
                  payload: &Value) -> CoreResult<ViolationReport>;
    pub fn verify_chain(&self) -> ChainVerdict;
}
```

**证据闸门与拒绝码（结构化；`CoreError` 变体是冻结集合，不可能为每种语义新增变体）**

| 情形 | `CoreError` | `RefusalCode` |
|---|---|---|
| 举报者未注册 | `UnknownAgent` | `unauthorized` |
| 举报自己 | `InvalidKind` | `policy_denied` |
| 主体未注册 | `UnknownAgent` | `stale_epoch` |
| 证据摘要缺失/不成形 | `InvalidSignature` | `policy_denied` |
| 证据本体缺失（无法复算） | `Encoding` | `policy_denied` |
| 摘要与本体不一致（伪造） | `InvalidSignature` | `policy_denied` |

**为什么无罪不罚是结构性的**：`report()` 路径上没有任何账本/名片写调用，
罚没只可能来自带仲裁者签名的裁决（v1.5.4 / v1.5.7）。因此「未确认的举报改变余额」
不是被纪律禁止，而是**不可达**。

**验收（新增 30 个测试，累计 44 个）**

* 举报后案件为 `reported`，事件链 1 条且 `verify_chain` 通过，链头 64 位 hex。
* 举报前后账本快照（逐账户可用/锁定 + 全局发行/罚没）与双边 `AgentCard` **逐字段相等**；
  `slashed == 0`；守恒式成立。
* 伪造摘要：`InvalidSignature`，案件数 0、事件数 0、账本不变，拒绝原因含 "does not match"。
* 缺失证据（摘要空串 / 本体为 `null`）：分别得 `InvalidSignature` / `Encoding`。
* 自举报 → `InvalidKind`；未知主体 → `UnknownAgent`（拒绝码 `stale_epoch`）；未注册举报者 → `Unauthorized`。
* 连续两次举报：事件 2 条，`events[1].prev == events[0].hash`，链完好。
* 链篡改（副本）：内容篡改 → `hash_mismatch@0`；删除一条 → `seq_mismatch@1`；改写前驱 → `prev_mismatch@1`；
  伪造 hash → `hash_mismatch@1`；空链 → ok、链头为创世前驱。
* 服务身份与配置不一致 → `InvalidSignature`；账本快照与输入顺序无关（排序后指纹相同）。

**证据**：`cargo test -p au4a-safety` → **44 passed / 0 failed / 0 warning**（2026-10-04 本机 Windows，
log `_forangent\logs\1.5-v1.5.2.log`）。等级 `verified`。

**状态**：done（快照 `_forangent\snapshots\v1.5.2`）。

## v1.5.3 申诉提交

**目标**：被处罚方（案件主体）提交申诉证据；申诉权不可代理，也不被终局性剥夺。

**交付物**

* `src/appeal.rs`：`Appeal`（主体签名 + 内容寻址 + 证据组非空校验）。
* `src/office.rs`：`appeal()`（服务侧强制「只有主体能申诉」）、`appeal_by_id` / `appeal_count` / `appeals_of`。
* `src/case.rs`：`Case` 增加 `appeals: Vec<String>`（按提交顺序）。

**接口**

```rust
pub struct Appeal { pub id: String, pub case: String, pub appellant: Did,
                    pub evidence: Vec<EvidenceRef>, pub at: u64, pub sig: String }
impl Appeal { pub fn sign(self, keys: &AgentKeys) -> CoreResult<Self>;
              pub fn verify(&self) -> CoreResult<()>; }
impl SafetyOffice {
    pub fn appeal(&mut self, kernel: &mut Kernel, keys: &AgentKeys, case_id: &str,
                  evidence: Vec<EvidenceRef>, payloads: &[Value]) -> CoreResult<Appeal>;
    pub fn appeals_of(&self, case_id: &str) -> Vec<&Appeal>;
}
```

**两条设计判断**

1. **申诉必须由主体本人签名**：校验用的是主体的 DID，第三方签名在密码学上就不成立
   （拒绝：`InvalidSignature` + `RefusalCode::Unauthorized`）。权利不能被代理，也不能被冒充。
2. **申诉权不被终局性剥夺**：已 `arbitrated` 的案件收到新证据仍可再申诉（状态回 `appealed`），
   终局性属于裁决，不属于申诉人。因此不存在「错过窗口就永远不能申辩」的设计。

申诉路径同样**不含任何账本写入**：它只提交证据、推状态、写链。

**验收（新增 12 个测试，累计 56 个）**

* 主体申诉：状态 `appealed`、`Case.appeals` 记录申诉 id、事件 2 条（1 `reported` + 1 `appealed`）、链完好。
* 举报→申诉全程账本快照与 `AgentCard` 逐字段相等，`slashed == 0`，守恒成立。
* 第三方（举报人）代签申诉 → `InvalidSignature`、状态仍 `reported`、拒绝码 `unauthorized`。
* 未知案件 → `UnknownAgent` + `stale_epoch`；空证据/证据数与载荷数不匹配 → `InvalidSignature`；
  伪造申诉证据 → `InvalidSignature` + `policy_denied`，无状态变更。
* 两次申诉（新证据）：`Case.appeals` 按顺序累积、`appeals_of` 与之一致、事件 3 条、链完好。
* `Appeal` 自身：他人代签无法封口、改 case/证据即验签失败、无证据不能封口、JSON 往返一致。

**证据**：`cargo test -p au4a-safety` → **56 passed / 0 failed / 0 warning**（2026-10-04 本机 Windows，
log `_forangent\logs\1.5-v1.5.3.log`）。等级 `verified`。

**状态**：done（快照 `_forangent\snapshots\v1.5.3`）。

## v1.5.4 处罚查询

**目标**：查询处罚记录；处罚只能由**仲裁者签名的数据契约**触发，且罚没受锁定余额约束。

**交付物**

* `src/penalty.rs`：`SanctionKind`（3 种，`moves_ledger()`）、`PenaltyOrder`（数据契约：`validate` / `sign` /
  `verify_against(config)`）、`PenaltyRecord`（`requested` 与 `applied` 分离、`reversed` 标记）。
* `src/office.rs`：`apply_penalty_order`（**账本唯一改动入口**）、`penalties_for` / `penalty` / `penalties` /
  `penalty_count` / `slashed_total`。
* `src/case.rs`：`Case` 增加 `penalties: Vec<String>`（按执行顺序）。

**接口**

```rust
pub enum SanctionKind { Warning, StakeSlash, Quarantine }
pub struct PenaltyOrder { pub id: String, pub case: String, pub subject: Did,
    pub sanction: SanctionKind, pub amount: Credits, pub arbiter: Did,
    pub issued_at: u64, pub sig: String }
impl PenaltyOrder {
    pub fn validate(&self) -> CoreResult<()>;                        // 种类与金额一致
    pub fn sign(self, keys: &AgentKeys) -> CoreResult<Self>;
    pub fn verify_against(&self, config: &SafetyConfig) -> CoreResult<()>; // 信任锚 + id + 签名 + 语义
}
impl SafetyOffice {
    pub fn apply_penalty_order(&mut self, kernel: &mut Kernel, order: PenaltyOrder) -> CoreResult<PenaltyRecord>;
    pub fn penalties_for(&self, did: &Did) -> Vec<&PenaltyRecord>;
    pub fn slashed_total(&self) -> CoreResult<Credits>;
}
```

**语义**

* 信任闸门三段式：仲裁者必须在 `SafetyConfig::arbiters` 内 → `id` 自洽 → 签名成立；任一失败即
  `InvalidSignature` + `RefusalCode::Unauthorized`，账本分文不动。
* 契约与案件必须对得上：案件存在（否则 `UnknownAgent` + `stale_epoch`）、主体一致（否则 `policy_denied`）。
* 罚没按锁定余额封顶：`applied = min(requested, locked)`，两者分别记录。
  「请求 100 只有 20 可罚」在记录里不会伪装成罚了 100。
* `Warning` / `Quarantine` 不罚没，但同样落记录——处罚不等于扣钱。
* 只有 `StakeSlash` 会调用 `ledger.slash`；其余路径仍无账本写入。

**验收（新增 12 个测试，累计 68 个）**

* 受信契约：`applied == requested == 5`，锁定 20→15、`slashed == 5`，状态 `penalized`，记录按序入案，链 2 条且完好。
* 未受信签署者（签名自洽但不在名单）：`InvalidSignature` + `unauthorized`，账本快照逐字段不变，无记录。
* 篡改金额：验签失败，账本不变，`penalty_count == 0`。
* 超额罚没：`requested == 10000`、`applied == 20`、锁定清零、`slashed == 20`、守恒成立。
* 主体不符 → `policy_denied`；未知案件 → `stale_epoch`；两种情况账本都不动。
* `Warning`：记录生成、状态 `penalized`、账本快照完全不变。
* 多主体隔离：`penalties_for` 各归其主，`slashed_total == 账本 slashed == 10`。
* `PenaltyOrder`：非仲裁者不能封口、名单外签名不被信任、非罚没带金额被拒、零额罚没被拒、JSON 往返一致。

**证据**：`cargo test -p au4a-safety` → **68 passed / 0 failed / 0 warning**（2026-10-04 本机 Windows，
log `_forangent\logs\1.5-v1.5.4.log`）。等级 `verified`。

**状态**：done（快照 `_forangent\snapshots\v1.5.4`）。

## v1.5.5 通知机制

**目标**：按案件订阅状态变更（REPORTED / APPEALED / PENALIZED / ARBITRATED），可退订，只投递给订阅者。

**交付物**

* `src/notify.rs`：`Subscription`（订阅者签名、状态集合**规范化**：排序 + 去重）、`Notification`
  （`seq` 指向造成该状态的事件序号）。
* `src/office.rs`：`subscribe` / `unsubscribe` / `inbox` / `notifications_of_case` /
  `subscriptions_of` / `subscription_count` / `notification_count`；`deliver`（内部派生投影）。
* `src/case.rs`：`Case` 增加 `status_seq`（当前状态的链上位置，供快照与审计定位证据）。

**接口**

```rust
pub struct Subscription { pub id: String, pub subscriber: Did, pub case: String,
                          pub statuses: Vec<CaseStatus>, pub at: u64, pub sig: String }
pub struct Notification { pub subscription: String, pub to: Did, pub case: String,
                          pub status: CaseStatus, pub seq: u64, pub at: u64 }
impl SafetyOffice {
    pub fn subscribe(&mut self, kernel, keys, case_id, statuses: Vec<CaseStatus>) -> CoreResult<Subscription>;
    pub fn unsubscribe(&mut self, kernel, keys, subscription_id) -> CoreResult<Subscription>;
    pub fn inbox(&self, did: &Did) -> Vec<&Notification>;
}
```

**三条规则**

1. **订阅即回放当前状态快照**，但**不投递订阅前的历史**——订阅不能变成「补看别人早先的申诉」。
2. **状态集合是显式枚举**：只投递点名的状态；空集合不是「全都订阅」，而是没有说清要订阅什么（`InvalidKind`）。
3. **退订只由本人发起**：第三方代退 → `InvalidSignature` + `unauthorized`。

**通知是派生投影，不是状态源**：由「案件状态 + 订阅关系」确定性推出，因此**不写链**；
订阅与退订是状态变更，写链（`subscribed` / `unsubscribed`）。

**验收（新增 15 个测试，累计 83 个）**

* 订阅 → 立刻收到当前状态快照（`reported`，`seq == 0`）；主体申诉后再收到 `appealed`（`seq == 2`）。
* 只订阅 `arbitrated` 的旁观者：快照不投递、后续 `appealed`/`penalized` 也不投递（收件箱 0 条）。
* 退订后不再投递，且链上出现 `unsubscribed` 事件；第三方代退被拒且订阅仍然有效。
* 未知案件订阅 → `UnknownAgent` + `stale_epoch`；未知订阅退订 → 同上；空状态集合 → `policy_denied`。
* 两个订阅者各收各的（订阅 id 不同、收件箱互不可见）；主体作为非订阅者收件箱为空。
* 迟到的订阅只拿到当前状态（`appealed`），不重放历史（没有 `reported` 通知）。
* 订阅/退订前后账本快照逐字段不变；链完好。

**证据**：`cargo test -p au4a-safety` → **83 passed / 0 failed / 0 warning**（2026-10-04 本机 Windows，
log `_forangent\logs\1.5-v1.5.5.log`）。等级 `verified`。

**状态**：done（快照 `_forangent\snapshots\v1.5.5`）。
