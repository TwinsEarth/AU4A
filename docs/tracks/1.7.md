# 轨道 1.7 — Committee Governance 委员会治理

* crate：`au4a-council`
* 版本区间：`v1.7.1 → v1.7.10`
* 依赖：`au4a-core`（冻结基元）、`au4a-kernel`（宿主内核）、`serde`、`serde_json`
* 时间来源：`au4a_core::LogicalClock`（本层不读墙钟、不做文件/网络 I/O、无全局可变状态）

## 设计立场（决定每一行代码）

1. **Agent 是主体**：动议只能由 Agent 提出。`crate::proposal::AgentIdentity` 必须由 `AgentKeys`
   派生才有实例，人类观察者的类型（`crate::veto::HumanObserver`）**没有**任何提案/修改方法——
   这不是约定，是编译期事实（`compile_fail` 文档测试把守）。
2. **人类只在极端情况有否决权**：`Veto` 只能把决议从「已通过」推到「已阻断」，
   不携带任何可修改决议的字段，行使时必须带非空公开理由。
3. **可复现**：选举与表决都是纯函数；同一份输入（无论消息到达顺序）得到同一个内容地址。
4. **可证伪**：文档里每条能力都指向一个真实测试名，做不到的写 `EvidenceGrade` 降级。

## v1.7.1 选举机制

**目标**：五类委员会（资源 / 任务 / 仲裁 / 进化 / 安全）由高信誉 + 长期在线的 Agent 选举产生，
结果确定、可复现，刷票（大量低信誉空壳 DID）无法当选。

**交付物**

* `src/committee.rs`：`CommitteeKind`（五类封闭枚举）、`Committee`、`Member`、BFT-lite 数学
  （`f = ⌊(n-1)/3⌋`、`quorum = n - f`、`is_bft_consistent`）。
* `src/election.rs`：`Candidate`、`ElectionBallot`（签名选票、绑定委员会类别）、`ElectionConfig`、
  `run()`（纯函数计票）、`ElectionOutcome`（含内容寻址 `id`、得分表、忽略票留痕）。
* `src/lib.rs`：`Council`（信誉账 + 在线时长账 + 委员会 + 选举日志）、`Council::elect()`、
  `self_check()`、`results_json()`、`scenario()`。
* `tests/election.rs`：8 个集成测试（正常 / 拒绝 / 不变式）。

**接口**

## v1.7.2 提案流程

**目标**：动议只能由 **Agent** 提出，且动议内容由 Agent 私钥签名；人类观察者在类型层面

  `ProposalDraft`（作者签名动议）。

* `src/lib.rs`：`Council::propose`（唯一提案入口）、`transition_to`（类型化状态机）、
  `CouncilEvent` 追加式事件日志、`proposals`/`proposals_of`/`proposal`。
* `tests/proposal.rs`：10 个集成测试。

## v1.7.3 表决机制

**目标**：BFT-lite 法定人数表决——`n ≥ 3f+1`、`quorum = n - f`；重复投票被拒；
**模棱两可（双签）作废整轮**；越权投票按单次恶意分类。

**交付物**

* `src/voting.rs`：`Choice`、`Vote`（签名票，绑定动议+轮次+选择）、`Tally`（计票与自洽断言）、
  `RoundOutcome`（`pending`/`passed`/`rejected`/`void_ambiguous`）、`VotingRound`、`RoundState`。
* `src/lib.rs`：`Council::open_round`、`Council::cast_vote`、`Council::round`/`current_round`/`rounds`、
  私有 `apply_state`（状态落地的唯一路径：先过状态机再记账）。
* `tests/voting.rs`：10 个集成测试。

**接口**

```rust
pub enum Choice { Yes, No, Abstain }
pub struct Vote { voter, proposal, round, choice, sig }   // cast(&AgentKeys, &str, u32, Choice) / verify()
pub struct Tally { yes, no, abstain, participation, n, f, quorum }  // outcome() / is_consistent()
pub enum RoundOutcome { Pending, Passed, Rejected, VoidAmbiguous }  // is_closed()
impl Council { open_round(&mut Kernel, &str) -> CoreResult<RoundState>,
               cast_vote(&mut Kernel, Vote) -> CoreResult<RoundState>,
               round(&str, u32) -> Option<RoundState>, current_round(&str) -> Option<RoundState> }
```

**验收（每条都对应真实断言）**

| 断言 | 测试 |
|---|---|
| `n=4` → `f=1`、`quorum=3`，第 3 张赞成票才出结论 | `quorum_is_n_minus_f_and_exactly_decides` |
| `n=7=3f+1` → `f=2`、`quorum=5=2f+1`，缺席 2 人仍能出结论 | `seven_member_committee_needs_five_and_tolerates_two_faults` |
| `no ≥ quorum` 时动议进入 `rejected` | `enough_no_votes_reject_the_motion` |
| 全票弃权（4/4）**不产生结论**，动议保持 `open` | `abstentions_never_produce_a_conclusion` |
| 同轮同选择重复投票被拒，本轮票数不变 | `a_duplicate_vote_in_the_same_round_is_refused_and_the_round_survives` |
| **双签作废整轮**：`void_ambiguous`、动议回到 `open`、作废轮不再收票、重开一轮可通过、作废留痕 | `an_ambiguous_double_vote_voids_the_whole_round` |
| 非委员投票 → `InvalidSignature` + `unauthorized`（单次即恶意） | `non_members_cannot_vote` |
| 篡改签名 / 投给未来轮次 → `InvalidSignature` / `InvalidVersion`（`stale_epoch`） | `forged_votes_and_wrong_rounds_are_refused` |
| 关闭轮次不再收票、已通过动议不能重开轮次或被改判 | `a_closed_round_takes_no_more_votes_and_there_is_no_second_conclusion` |
| 计票自洽：`yes+no+abstain = participation ≤ n`，`yes/no` 不可能同时达法定人数 | `voting.rs` 单元测试 + 自检项 `council.votes.tally_consistent`、`council.votes.members_only`、`council.rounds.decided_matches_proposal` |

**证据**

```text
$env:CARGO_TARGET_DIR = "E:\DS\_forangent\target\au4a-council"
cargo test -p au4a-council      # EXIT=0
→ 单元测试 20 passed; 0 failed
→ tests/election.rs 8 passed; 0 failed
→ tests/proposal.rs 10 passed; 0 failed
→ tests/voting.rs 10 passed; 0 failed
→ doc-tests 3 passed; 0 failed
→ 本 crate 0 warning
```

实现过程中被测试逼出来的两条真实修正（记录在案）：

1. 让全体委员都投票的写法会在动议已通过后再投一票 → 说明「达到法定人数即出结论」必须显式
   在轮次关闭时停止投票，不能靠「大家都投一遍」。
2. 投给**已关闭轮次**的迟到票原本先撞上「动议不在 open」的分支被判 `conflict`；现在把轮次检查
   前移，迟到票按 `stale_epoch`（竞争语义，不升级为恶意）处理——与冻结基元「竞争不要误伤」一致。

证据等级：`verified`（本机 Windows 实测；投票全部真实签名与验签）。
留痕说明：跨节点投票广播属网络层（v1.9），本版是本地内存内核上的真实执行。

## v1.7.4 执行引擎

**目标**：把**已通过**的决议落成真实状态变更（策略 / 信誉 / 账本），只能执行 `passed` 的动议，

**交付物**

* `src/execution.rs`：`ExecutionEffect`（策略/信誉/转账/罚没）、`ExecutionReceipt`（含账本前后快照

* `src/lib.rs`：`Council::execute`、`policy`/`policies`、`execution`/`executions`、

## v1.7.5 否决权（本项目「人类只观察」的核心证据）

**目标**：人类在治理层只有**一个**写能力——否决；且它在**类型层面**只能阻断，
不能提案、不能改写、不能表决、不能执行，理由必须公开。

**结构性论证（三层，都可被机器检验）**

| 层 | 机制 | 证据 |
|---|---|---|
| 类型层 | `Veto` 字段只有 `id / observer / proposal / reason / at`，**没有** `action`/`patch`/`alternative`/`sig` 字段；唯一构造入口是 `HumanObserver::veto`；不实现 `Deserialize`（不能凭空反序列化一张否决） | `veto.rs` 的 2 个 `compile_fail` 文档测试（`veto.propose` / `veto.edit_proposal` 不存在）+ 运行期测试逐个字段断言载荷里没有可执行内容 |
| 能力层 | `HumanObserver` 不含任何密钥：`propose` / `edit_proposal` / `cast_vote` / `execute` 四个方法**都不存在**（`compile_fail` 4 段），而这三件事分别需要 `AgentIdentity`、`AgentKeys` 签名 | `human.rs` 的 4 个 `compile_fail` + 1 个正例文档测试 |
| 状态机层 | 否决只有一条出路：`Open|Passed → Blocked`（终态）。阻断后不可执行、不可复活、不可重开轮次、不可二次否决；决议内容与动议总数都不变 | `tests/veto.rs` 8 个集成测试 + 自检项 `council.veto.blocks_only` / `council.veto.read_only` |

**交付物**

* `src/veto.rs`：`Veto`（只读访问器 + `payload()` 只读投影）、`HumanVeto`、`VetoReceipt`、
  `apply()`、`vetoable()`、`is_blocked()`、`vetoed_by()`、`label_has_no_did()`、
  `observer_is_not_an_agent()`；含 2 个 `compile_fail` 文档测试。
* `src/human.rs`：`HumanObserver::veto`（唯一写能力）、`HumanView.vetoes`；
  `compile_fail` 从 2 段扩到 4 段（propose / edit_proposal / cast_vote / execute）。
* `src/lib.rs`：`Council::apply_veto` / `veto_record` / `vetoes`、否决不变量自检、
  scenario 增加「第二条动议 → 通过 → 人类否决 → 执行被拒」。
* `tests/veto.rs`：8 个集成测试。

**接口**

```rust

               fn veto_record(&self, &str) -> Option<&Veto>, fn vetoes(&self) }
```

**验收（每条都对应真实断言）**

| 断言 | 测试 |
|---|---|
| 否决把已通过动议推入 `blocked`；决议内容、动议总数、策略表全部不变 | `a_human_veto_blocks_a_passed_motion_and_nothing_else_changes` |
| 被阻断后：执行被拒、不能复活为 passed/executed、不能重开轮次、不能二次否决 | `a_blocked_motion_can_never_be_executed_or_revived` |

| 已执行的动议不可被事后否决（否决不能回滚） | `an_executed_motion_cannot_be_vetoed_retroactively` |
| 否决不存在的动议被拒（`UnknownAgent`），不产生记录 | `vetoing_an_unknown_proposal_is_refused` |
| Agent 侧没有否决路径；执行后的终态不可被任何 Agent 改写 | `the_agent_side_has_no_veto_path` |

## v1.7.7 测试（不变式 + 确定性重放）

**目标**：把「治理过程是否始终自洽」变成**可执行、可复现的证伪器**，而不是靠人工检查。

**交付物**

* `src/invariants.rs`：
  * `INVARIANT_NAMES`（17 条不变式的公开清单）；
  * `state_digest()`——整个治理状态的内容地址；
  * `check_all()`——`Council::checks()`（14 条）+ 3 条跨对象一致性检查
    （事件主题可解析 / 表决轮所属委员会仍在任且 `n`、`quorum` 一致 / 策略键合法）；
  * `replay(seed, steps)`——确定性 LCG 驱动的治理历史重放，
    **每一步之后**跑全部不变式，返回 `ReplayReport`（含各类结局计数与最终摘要）；
  * `replay_report()`——多种子重放的 JSON 摘要。
* `src/lib.rs`：自检项 `council.replay.invariants`、`council.replay.coverage`；
  `results_json().invariants`（清单长度、状态摘要、三种子重放报告）。
* `tests/invariants.rs`：8 个集成测试。

**重放覆盖的操作**：委员提案（四种动作）、开轮、单张随机票（赞成/反对/弃权）、
**同轮改投（双签作废）**、**非委员越权投票**、**协同推进至法定人数**、执行、人类否决
（含空理由拒绝路径）、对终态动议的非法操作。

**验收（每条都对应真实断言）**

| 断言 | 测试 |
|---|---|
| 同一种子两次重放**逐字段相同**（含状态摘要） | `replay_is_deterministic_across_runs` |
| 4 个种子 × 90 步：0 违例，且四种结局（执行/阻断/作废/否决）都被真实触发 | `replay_exercises_every_failure_mode_and_holds_invariants` |
| 不同种子给出不同治理历史（摘要不同） | `different_seeds_produce_different_histories` |
| 摘要对每一次状态变更都变化，只读观察不改变摘要，重复计算稳定 | `state_digest_tracks_every_state_change` |
| **不变式清单与实现严格相等**（两个方向断言：删掉或新增都变红） | `the_invariant_list_is_exactly_what_is_enforced` |
| 重放报告机器可读（每种子违例数为 0、摘要为 64 位 hex） | `replay_report_json_is_machine_readable` |
| `steps = 0` 是合法空操作且摘要可复现 | `zero_steps_is_a_valid_no_op` |
| 自检项携带重放证据；`results_json` 含清单长度与三种子报告 | `self_check_reports_the_replay_evidence` |

**证据**

```text
cargo test -p au4a-council      # EXIT=0
→ 单元 23 + election 8 + execution 10 + invariants 8 + ongov 6 + proposal 10 + veto 8 + voting 10 = 83 passed; 0 failed
→ doc-tests 7 passed; 0 failed
→ 本 crate 0 warning
```

重放实际跑出来的数字（自检项 detail 里可见，可在 `results_json` 复核）：
`seed=0x1707, steps=72 → 33 条动议 / 11 轮表决（双签作废 >0）/ 执行 >0 / 人类阻断 >0 / 拒绝 >0，
17 条不变式 × 每步全部通过`。

诚实说明（成本）：`self_check()` 会真的跑一遍 72 步重放，因此它比「只返回常量的自检」
慢若干秒。这是刻意的取舍——**自检必须能失败**，否则它只是装饰。
