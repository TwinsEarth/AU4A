# 轨道 1.7 — Committee Governance 委员会治理

* crate：`au4a-council`
* 版本区间：`v1.7.1 → v1.7.10`
* 依赖：`au4a-core`（冻结基元）、`au4a-kernel`（宿主内核）、`serde`、`serde_json`
* 时间来源：`au4a_core::LogicalClock`（本层不读墙钟、不做文件/网络 I/O、无全局可变状态）

## 设计立场（决定每一行代码）

1. **Agent 是主体**：动议只能由 Agent 提出。`crate::proposal::AgentIdentity` 必须由 `AgentKeys`
   派生才有实例，人类观察者的类型（`crate::veto::HumanObserver`）**没有**任何提案/修改方法——
   这不是约定，是编译期事实（`compile_fail` 文档测试把守）。
2. **人类只在极端情况有否决权**：`Veto` 只能把决议从「已通过」推到「已阻断」，
   不携带任何可修改决议的字段，行使时必须带非空公开理由。
3. **可复现**：选举与表决都是纯函数；同一份输入（无论消息到达顺序）得到同一个内容地址。
4. **可证伪**：文档里每条能力都指向一个真实测试名，做不到的写 `EvidenceGrade` 降级。

## v1.7.1 选举机制

**目标**：五类委员会（资源 / 任务 / 仲裁 / 进化 / 安全）由高信誉 + 长期在线的 Agent 选举产生，
结果确定、可复现，刷票（大量低信誉空壳 DID）无法当选。

**交付物**

* `src/committee.rs`：`CommitteeKind`（五类封闭枚举）、`Committee`、`Member`、BFT-lite 数学
  （`f = ⌊(n-1)/3⌋`、`quorum = n - f`、`is_bft_consistent`）。
* `src/election.rs`：`Candidate`、`ElectionBallot`（签名选票、绑定委员会类别）、`ElectionConfig`、
  `run()`（纯函数计票）、`ElectionOutcome`（含内容寻址 `id`、得分表、忽略票留痕）。
* `src/lib.rs`：`Council`（信誉账 + 在线时长账 + 委员会 + 选举日志）、`Council::elect()`、
  `self_check()`、`results_json()`、`scenario()`。
* `tests/election.rs`：8 个集成测试（正常 / 拒绝 / 不变式）。

**接口**

```rust
pub enum CommitteeKind { Resource, Task, Arbitration, Evolution, Security }  // + ALL/as_str/parse/title/mandate/has_emergency_channel
pub struct Committee { kind, epoch, seats, elected_at, election_id, members }
impl Committee { size, member, has_member, fault_bound, quorum, is_bft_consistent, member_dids }
pub struct ElectionBallot { voter, committee, choices, sig }
impl ElectionBallot { cast(&AgentKeys, CommitteeKind, &[Did]) -> CoreResult<Self>, verify() -> CoreResult<()> }
pub fn election::run(kind, epoch, &ElectionConfig, &[Candidate], &[ElectionBallot], at) -> CoreResult<ElectionOutcome>
impl Council { new, config, now, tick, note_reputation, note_uptime, reputation, uptime,
               committee, committees, elections, roster, checks, elect(&mut Kernel, CommitteeKind, &[ElectionBallot]) }
```

**验收（每条都对应真实断言）**

| 断言 | 测试 |
|---|---|
| 五类委员会名字往返一致，紧急通道只有安全委员会持有 | `five_committee_kinds_are_stable_and_security_holds_the_channel` |
| 高信誉 + 长期在线者按得分当选，`n=5` 时 `f=1`、`quorum=4` | `high_reputation_long_online_agents_win_the_seats` |
| 同一输入（含选票乱序）选举 `id` 逐字节相同，epoch 递增 | `election_is_reproducible_across_runs_and_ballot_order` |
| 60 个信誉为零的空壳 DID 投票后当选名单与基线完全一致，忽略票全部留痕 | `sybil_flood_cannot_win_or_shift_the_outcome` |
| 伪造签名 → `InvalidSignature`；跨委员会重放 → `InvalidKind`；未注册选民 → `UnknownAgent`；重复投票 → `DuplicateAgent` | `forged_replayed_and_foreign_ballots_are_refused_with_typed_reasons`、`duplicate_and_foreign_voters_are_typed_errors` |
| 空委员会 `quorum = 0` 但**不具备表决资格**（否则 0 票会自动通过） | `an_empty_committee_has_no_voting_capacity` |

## v1.7.2 提案流程

**目标**：动议只能由 **Agent** 提出，且动议内容由 Agent 私钥签名；人类观察者在类型层面
没有任何提案/修改能力——这是本项目「人类只观察」的核心证据。

**交付物**

* `src/proposal.rs`：`Action`（动议动作数据：策略 / 信誉 / 转账 / 罚没）、`ProposalState` 状态机、
  `Proposal`、`AgentIdentity`（能力凭证，字段私有、不实现 `Deserialize`）、
  `ProposalDraft`（作者签名动议）。
* `src/human.rs`：`HumanObserver`（只读投影 `HumanView`）、`observe_json`、`observed_dids`；
  含 **2 个 `compile_fail` 文档测试**（`propose` / `edit_proposal` 不存在）+ 1 个正例文档测试。
* `src/lib.rs`：`Council::propose`（唯一提案入口）、`transition_to`（类型化状态机）、
  `CouncilEvent` 追加式事件日志、`proposals`/`proposals_of`/`proposal`。
* `tests/proposal.rs`：10 个集成测试。

**接口**

```rust
pub enum Action { SetPolicy{key,value}, SetReputation{did,reputation_bp}, Transfer{from,to,amount}, Slash{did,amount} }
pub enum ProposalState { Open, Passed, Rejected, Blocked, Executed }   // can_transition_to / is_terminal
pub struct AgentIdentity;  impl AgentIdentity { from_keys(&AgentKeys) -> Self, did() -> &Did }  // 无 Deserialize / 无 pub 字段
pub struct ProposalDraft { author, committee, title, action, sig }
impl ProposalDraft { by(&AgentKeys, CommitteeKind, title, Action) -> CoreResult<Self>, verify() -> CoreResult<()>, id() }
impl Council { propose(&mut Kernel, &AgentIdentity, ProposalDraft) -> CoreResult<Proposal>,
               transition_to(&mut Kernel, &str, ProposalState) -> CoreResult<Proposal>,
               proposal(&str), proposals(), proposals_of(CommitteeKind), events(), record_event(...) }
pub struct HumanObserver;  impl HumanObserver { new(label), label(), observe(&Council) -> HumanView }
```

**验收（每条都对应真实断言）**

| 断言 | 测试 |
|---|---|
| 委员 Agent 可提案，id 可由（作者/委员会/标题/动作）复算 | `a_seated_agent_can_propose_and_the_motion_is_content_addressed` |
| 非委员 Agent 提案 → `InvalidSignature` + `unauthorized` 留痕 | `a_non_member_agent_cannot_propose` |
| 未注册身份提案 → `UnknownAgent`；未选出委员会的动议 → `StaleEpoch` | `an_unregistered_identity_cannot_propose`、`a_proposal_for_an_unseated_committee_is_refused` |
| 同内容动议重复提交 → `DuplicateAgent` + `conflict` 留痕（内容寻址去重） | `identical_motions_are_deduplicated_by_content_address` |
| 篡改动议内容（金额 5 → 500）后签名失效，动议进不了治理层 | `tampered_content_never_reaches_the_council` |
| 非法动作（零额转账 / 信誉 > 10000bp / 空标题）在提案阶段被拒，零状态变更 | `illegal_actions_and_titles_are_refused_before_any_state_change` |
| 状态机拒绝 `open→executed`、`passed→rejected`、终态再迁移 | `the_state_machine_refuses_illegal_transitions` |
| 观察者投影只读：同一状态观察两次结果完全相同，且不产生任何治理事件 | `the_human_observer_is_read_only` |
| **人类没有 `propose` / `edit_proposal`**（编译期证据） | doc-tests：`human::HumanObserver` 的两段 `compile_fail` |

运行期（`HumanView` 只有只读字段、观察不改变状态）与编译期（`compile_fail` 文档测试）。
说明：`AgentIdentity` 刻意不实现 `Deserialize`，避免「反序列化出一个身份」这条旁路。
