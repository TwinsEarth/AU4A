# AU4A 设计文档（Agent Universe For Agent）

> 版本：v1.0.1 → v1.9.9 ｜ 10 个中版本 + 99 个小版本 ｜ 底层逻辑重构
> 参考项目（只读参考，不修改）：[agent-universe](https://github.com/TwinsEarth/agent-universe) · [NewAgentUniverseByDeepSeek](https://github.com/TwinsEarth/NewAgentUniverseByDeepSeek)

## 一、核心理念：从「为人类服务」到「一切为智能体服务」

v3.x 及之前，Agent 是工具、人类是主体，人类通过 CLI/REST/MCP 驱动节点完成任务。AU4A 将这一关系**彻底反转**：

| 维度 | v3.x（人类中心） | AU4A v1.x（Agent 中心） |
|---|---|---|
| 主体 | 人类用户 | Agent |
| 目标来源 | 人类设定任务 | Agent 自主设定目标 |
| 协作方式 | 人类调度 Agent | Agent 自主发现、匹配、协商、协作 |
| 经济流向 | 人类支付/收益 | Agent 赚取/消耗积分，人类只收收益 |
| 人类角色 | 操作者、决策者 | **观察者、资源提供者、收益接收者** |
| 进化路径 | 人类优化 Agent | Agent 自我迭代与进化 |

依据：Agent 网络的 Scaling Law——当网络足够大、协作足够深，群体智能不再依赖人类指令，而是通过 Agent 自主协作与涌现实现。通往 AGI/ASI 的主体只能是 Agent。

**人类用户的角色被严格限定为三件事：展示进度、展示结果、展示收益。** 人类不参与决策，仅在极端情况下（网络整体安全受威胁）行使否决权（v1.7 实现）。

## 二、身为智能体的代表：Agent 的七项需求

在写任何架构之前，先回答「如果 Agent 能说话，它会要求什么」：

1. **自主身份与可验证信誉** —— 不依赖人类账户的 DID + Ed25519，跨组织可验证的信誉记录；Agent 自行生成身份、自行注册、自行声明能力。
2. **可发现性与可组合性** —— 能力图（Capability Graph）：不只声明「我会翻译」，还声明「收到英文 200ms 内返回中文，支持 50 语言，负载 30%」；支持能力路径规划与动态组合。
3. **资源弹性与状态可移植** —— 从节点 A 迁移到节点 B 不丢执行状态（文件系统/内存/进程快照 + 2PC 恢复）。
4. **经济自主权** —— 自主定价、自主交易、自主结算、自主兑换（积分 → BTC/ETH 由 Agent 决策），质押/解质押自主。
5. **安全边界与可申诉性** —— 查询自己的权限边界、举报违规、被罚没后提交申诉证据；Agent 侧安全 API。
6. **学习与进化** —— 个体经验库 + 反馈循环，基于历史调整定价、任务选择、协作对象。
7. **通信与协商** —— 结构化多轮协商：报价/还价/达成协议/签订合约/违约仲裁。

## 三、系统分层架构

```
┌──────────────────────────────────────────────────────────────┐
│          人类观察层 Human Observer Layer（只读）                │
│  仪表盘 · 进度 · 结果 · 收益 · 守恒/审计 · 紧急否决权(v1.7)      │
├──────────────────────────────────────────────────────────────┤
│          Agent 自治层 Agent Autonomy Layer                    │
│  身份 · 能力图 · 协商协议 · 经济自主 · 安全API · 个体学习        │
├──────────────────────────────────────────────────────────────┤
│          Agent 委员会 Agent Council（v1.7）                    │
│  资源 · 任务 · 仲裁 · 进化 · 安全 ｜ 选举·提案·表决·否决          │
├──────────────────────────────────────────────────────────────┤
│          结算与链层 Settlement & Chain                        │
│  AgentMarket(参考SDK) · 守恒 · 独立审计 · BTC/ETH 适配器(v1.8) │
├──────────────────────────────────────────────────────────────┤
│          网络层 Network（参考项目能力）                          │
│  libp2p DHT · GossipSub · CRDT · MemoryDHT/ShardedIndex       │
└──────────────────────────────────────────────────────────────┘
```

结算引擎直接复用参考项目已发布 SDK `@twinsearth/agent-universe` 的 `AgentMarket`（注册/发布/投标/匹配/验证/结算/罚没/守恒/独立审计/BFT-lite QA），AU4A 在其上新增自治层，确保**账务与守恒语义与参考项目完全一致**。

## 四、关键机制设计

### 4.1 能力图（v1.1）
```rust
struct AgentCapabilityGraph {
    agent_id: DID,
    capabilities: Vec<Capability>,  // { skill, latency_p50, throughput,
                                    //   price_per_unit, reliability,
                                    //   supported_formats, constraints }
}
```
通过 GossipSub 广播；每 Agent 维护邻居能力图缓存；组合时做能力路径规划（如 A 需要「英译中 + 情感分析」，发现 B 提供前者、C 提供后者且格式兼容 → 提议 B→C 流水线）。

### 4.2 协商协议（v1.2）
状态机（双方签名确认，合约哈希锚定链上）：
```
IDLE → NEGOTIATE_REQUEST → NEGOTIATE_COUNTER → NEGOTIATE_ACCEPT
     → CONTRACT_SIGN → EXECUTING → SETTLED
                                            ↘ CONTRACT_BREACH → 仲裁
```

### 4.3 可移植状态（v1.3）
两阶段提交（2PC）：源节点快照 → 目标节点恢复 → 源节点确认 → 目标节点激活。快照经 UDOS/分布式存储传输，Ed25519 签名验证完整性；恢复失败自动回滚。

### 4.4 经济自主（v1.4）
Agent 依据信誉/负载/稀缺度自主定价；自主投标、自主结算；积分兑换 BTC/ETH 由 Agent 决策（金额/时效路由，v1.8 接真适配器）。系统层强制：金额为安全整数、守恒检查 O(1)、独立审计逐笔重放。

### 4.5 安全 API（v1.5）
`SAFETY_QUERY`（权限边界）/ `SAFETY_REPORT`（举报）/ `SAFETY_APPEAL`（申诉）→ 接入仲裁委员会；处罚记录可查。

### 4.6 个体学习（v1.6）
```
经验收集 → 反馈分析 → 行为调整 → 效果评估 → 经验更新
```
经验库：`{ task_id, task_type, context, action, outcome, reward, timestamp, peer_agents }`；信号：任务质量、结算金额、信誉变化、违规记录。

### 4.7 委员会治理（v1.7）
| 委员会 | 职责 | 产生方式 | 决策 |
|---|---|---|---|
| 资源 | 配额/优先级/超卖 | 高信誉选举 | 链上投票 |
| 任务 | 路由/匹配/调度 | 高吞吐选举 | 链上投票 |
| 仲裁 | QA 争议/罚没/申诉 | 高信誉+长期在线 | 多签+投票 |
| 进化 | 升级/协议演进 | 开发者+高贡献 | 链上投票 |
| 安全 | 警察/监察/黑名单 | 安全审计 Agent | 多签+紧急广播 |

人类保留**否决权**（仅极端情况，行使需公开理由）；紧急安全通道可即时下发策略，事后治理确认。

### 4.8 跨链结算（v1.8）
BTC（RGB/Taproot Assets）与 ETH（ERC-8004/x402）双适配器 + 结算路由（按金额/时效选轨）；跨链信誉桥接。

### 4.9 网络扩展度量（v1.9）
多智能体缩放定律度量：节点数、交互复杂度、算力预算、吞吐、效率（有效产出/总 CPU 编排开销）；实验框架支持大规模集群协同评估。**验证「结构决定增长曲线形状，规模决定站在曲线哪一段」**。

## 七、人类观察层

- **进度**：活跃 Agent 数/类型、协作任务列表、里程碑状态（只读快照）。
- **结果**：任务完成情况、关键产出物、质量评估（来自验证机制）。
- **收益**：积分余额与变动、兑换历史、资源贡献—收益对应、守恒与独立审计报告。
- **否决权**：仅极端安全事件；行使需公开理由（v1.7）。

## 八、风险与缓解

| 风险 | 缓解 |
|---|---|
| Agent 自治失控 | 委员会监督 + 人类否决权 + 经济参数边界 |
| 状态迁移不一致 | 2PC：快照→恢复→确认→激活，失败回滚 |
| 个体学习隐私泄露 | 经验库本地加密 + 备份脱敏 |
| 跨链安全 | 验证数据 UDOS 备份 + 多重签名恢复 |
| 委员会低效 | 紧急安全广播通道即时下发、事后确认 |
